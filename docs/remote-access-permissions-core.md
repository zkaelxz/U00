## Step 133: permission model as built

`BAIHE_API_AUTH=off` (default) keeps today's behaviour for the owner at the PC: every request is the local owner with every permission, no session, no CSRF. Because of that, off mode serves only direct loopback requests: `LoopbackOnlyGate` answers a generic 403 to any request with a non-loopback peer, Host or Origin, or with any proxy/forwarding header (`X-Forwarded-*`, `Forwarded`, `Via`, `X-Real-IP`, ...), on every path including `/api/health` and the frontend (a proxied health check must not report a server it would refuse to serve). A non-loopback `BAIHE_API_HOST` is also refused at startup (`python -m api` and `create_app`); the env check alone could not stop a same-PC reverse proxy or `uvicorn --host`, the request-time gate does. The gate also blocks DNS rebinding (the Host is the attacker's name). `on` enforces the rules below. Catalogue (`services/auth_service.py`): household defaults `library.read`, `lines.read`, `lines.edit`, `jobs.start`, `jobs.cancel`, `review.use`; off by default `media.import_url`, `sources.import`, `engines.paid`, `extension.send`, `media.stream`; admin-only (from the `is_admin` flag, never grantable) `admin.library`, `admin.settings`, `admin.diagnostics`, `admin.users.read`, `admin.users`, and `media.upload` (admin uploads, below; outside the `admin.*` family and its view/write split). Each admin permission is classified view, away write or write (`ADMIN_VIEW_PERMISSIONS` / `ADMIN_AWAY_WRITE_PERMISSIONS` / `ADMIN_WRITE_PERMISSIONS`; unlisted counts as write, and `tests/test_api_household_listener.py` fails on an unclassified one): view is `admin.users.read` only; away write is `admin.users` (member accounts from away, 2026-10-30; admin targets stay PC-only); `admin.library`, `admin.settings` and `admin.diagnostics` mix reads with writes, so they are write as a whole. `local_only()` means a direct loopback request at the PC (no proxy headers, loopback Host/Origin), with no session needed; it is how "uploads, deletes and settings are PC-only" is enforced; on the D5 household listener ([`remote-access-listeners.md`](remote-access-listeners.md)) it refuses every request. In both modes a POST/PUT/PATCH to a `local_only()` route must also be `application/json` or carry `X-Baihe-Local: 1`, so a page on another loopback port cannot reach it with a no-cors "simple" request (text/plain, form-urlencoded or multipart); With auth off the same rule covers every `/api` POST/PUT/PATCH, not just `local_only()` routes: off mode has no CSRF token and the Origin check ignores the port, so otherwise a page on another loopback port (a dev server, say) could start a paid LLM run or cancel a job with a bodyless POST. With auth on, every non-GET already needs the session's CSRF header (a custom header, so it forces a preflight), and the rule stays scoped to `local_only()` routes. DELETE and GET are unaffected. The React client (`postJson`, `deleteJson`, `postMultipart`) sends `X-Baihe-Local: 1` on every mutating request. `LocalOnlyCrossSiteGate` applies this before the request body is read. The Origin port is still not compared with the API's own; the content-type/header rule makes that unnecessary for mutations. `tests/test_api_permissions.py` fails if any route lacks exactly one declaration.

The route -> permission table (one row per declaration, with every method and path) is in [`route-permissions.md`](route-permissions.md); `tests/test_api_permissions.py` fails when it drifts from the app.

Judgement calls:
- **Shutdown (Step 80b).** `POST /api/system/shutdown` is `local_only()` and additionally needs the one-time token the installed launcher started the server with (`X-Baihe-Shutdown-Token`, compared in constant time); without that token in the server's environment the route is a 404, so a source checkout's server has no shutdown route. It cancels this process's jobs through `jobs_service.cancel_job`, then makes uvicorn exit (`services/shutdown_service.py`).
- **App updates.** Every `/api/system/update*` route is `local_only()` (and under `/api/system/`, which the household proxy refuses): the status, the check (one unauthenticated GET of the public GitHub releases API for the repository in `BAIHE_UPDATE_REPO`, default `zkaelxz/U00`), the once-a-day-check toggle (off by default), the download and starting Setup. Downloading and installing each need a click; install also needs `confirm=true`, Windows, an installed copy, a download whose SHA-256 matched the release's `.sha256`, no download and no job running; Setup is started from a private temp copy that is hashed again, with the server's environment minus the shutdown token, the job name and secret-named variables (the job allows breakaway only for that launch), and the server is not stopped by the route (Setup stops it once the user clicks Install there). Requests are https to `api.github.com` (API: the first page of releases, the newest `v*` one with the installer and its `.sha256`) or `github.com` / `objects.githubusercontent.com` / `release-assets.githubusercontent.com` (download) only, every redirect hop is checked, and no credentials are sent. The SHA-256 comes from the same release, so it catches a broken download but is not a signature; the installer is unsigned. Responses carry versions, the installer's file name, sizes and booleans: no URL, no path (`services/update_service.py`).
- **Paid engines.** Routes that can call an LLM (`translate-run/.../run`, `translate-run/.../glossary-affected/run` (the same run limited to the lines a glossary change affects; its preview `GET .../glossary-affected` is `lines.read` because it returns line text, and makes no engine call), the five `review-jobs`, `narration/.../run`, `metadata/.../autofill`, `metadata/.../research` (Step 37 grounded research; always Gemini), `lines/.../retry-blocked` (the blocked-line retry; its engine check runs before body validation), `restructure/.../resegment` when `use_llm` is true, `restructure/.../resegment/preview-llm` (parity R47: an LLM preview job that writes no lines; its result, which carries line text, is read back with the `lines.read` GET of the same path, never through `/api/jobs`; `resegment` with `use_preview: true` commits that stored preview under `lines.edit` with no LLM call, so it needs no engine check), `review-extras/.../style/learn` (learn my style) and `glossary/.../from-lines` (`POST /api/glossary/dramas/{id}/from-lines`, extract terms from the lines), `sources/{name}/import/{chapter_id}/ai-recover` (`sources.import`; one confirmed AI call on a chapter whose page layout changed, engine required in the body, ending in a Review extraction; no spending-cap check, like the pasted-URL AI fallback)) declare `jobs.start` (or `media.import_url`) and the handler calls `require_engines_allowed` with every engine the request names (including a translate fallback chain). Without `engines.paid` only `translate_engines.FREE_ENGINES` pass; an omitted engine (the configured default) and Gemini (free tier is a per-key setting) count as paid. `POST /api/translate` is an ad-hoc LLM call and declares `engines.paid` outright; it also refuses a capped engine once the monthly spending cap is used up and logs its usage (`translate_text`). A request's `free_tier`/`gemini_free_tier` can only switch the Gemini free tier off: it counts as on only when the saved setting is on too. `line-ai` improve/explain/alternatives/grammar (`lines.read`; improve/explain were `engines.paid` until the owner decision of 2026-10-14 let members use them with a free engine) and `lines/.../shorten-overlong` (`lines.edit`) call `require_engines_allowed` instead, on the engine the call will use: the named one, else the drama's own translation engine, resolved on the server before the check and passed on to the call. Since Step 36, when the drama has no engine or a translation-only one, the line helpers (Improve, Why this?, Alternatives, Grammar, Shorten) use the Settings "Line helpers for translation-only engines" engine (`llm.instructions`; unset, the Settings default engine, which may be paid) instead of refusing; that is the name the paid-engine check sees. So a household user can run them on a drama that uses a free engine (Ollama), even though the React client names no engine. Shorten also needs `confirm: true` and is refused (409) while a job runs for the drama; all three refuse a paid engine once the monthly spending cap is used up. Groq cloud transcription is paid too: `POST /api/transcribe/.../config` with `use_groq: true`, and `POST /api/transcribe/.../run` for a drama whose stored config has `use_groq` on, need `engines.paid` (`require_paid_engines`). Audited (2026-09-29): every service that resolves an engine key or builds an engine (`line_ai`, `metadata`, `narration`, `restructure`, `review_jobs`, `translate_run`/`workspace_job`, `translate`, `transcribe`, `blocked_retry`, `review_extras` (style learn), `glossary_service` (from-lines), `metadata_research` (Step 37: always Gemini; a lookup with fewer than 5 free grounded searches left also needs `allow_paid: true`, is refused on a free-tier key, and is checked against the monthly cap assuming 5 paid queries; `research_id` is per lookup and bound to the drama)) is behind one of these checks. The episode-summary engine chosen in Settings (`translate_run_service.pick_summary_engine`, used by `translate-run/.../run` and `library/admin/bulk/translate`) is not named in the request, so instead of refusing the run it is skipped when it is outside `FREE_ENGINES` and the caller lacks `engines.paid` (`api.auth.holds_paid_engines` → `allow_paid_summary`), and a paid summary call is skipped once the monthly cap is used up (`translation_finish.finish_translation_run`) (security review of PR #439, 2026-09-29); `translate-run/.../bulk/resume` calls `require_engines_allowed` on the engine of every bulk job it would restart, since a resumed off-peak run submits its batch and a Reflect run sends its next stage; dub/audiobook TTS (OmniVoice) is free/local; diarization uses a free Hugging Face token. Step 99's "Try with the stronger engine" (`POST /api/stronger-engine/dramas/{drama_id}/lines/{line_id}/try`, `review.use + lines.read`: the result carries the line's English) also runs `require_engines_allowed` on the engine Settings picked for "Stronger translation for hard lines"; the body names no engine, and nothing is written (the client applies the text through the line patch).
- **Ollama cloud models.** Ollama is in `FREE_ENGINES`, but a hosted tag (`is_ollama_cloud_model`: ends `-cloud` or `:cloud`) sends the text off the PC and uses the owner's Ollama quota, so naming one in a translate run (including a fallback entry), a glossary re-translate, a Live session, a saved preset or any other model-taking route (line tools, review jobs, Reader, narration, restructure, style learning, compare-transcription) needs `engines.paid` or the member's own Ollama key (`require_engines_allowed(..., model=)` / `require_cloud_model_allowed`); local tags stay free. A member who saved their own Ollama key (Settings > Your Ollama key, owner decision 2026-10-14) passes this check without `engines.paid`, because their cloud runs go to ollama.com with their key and spend their own quota (`services/member_key_service.py`); the key lifts only this check, never a paid engine. The key is stored encrypted with a server secret in `.env`, is never returned (last four characters only), is left out of backups, and an admin can remove but not read it. A key that is saved but can no longer be decrypted (lost or changed secret) refuses that member's cloud tags, even with `engines.paid`, rather than running them on the owner's account. Admins keep the PC's sign-in and can't save one. Removing your own key (`DELETE /api/auth/ollama-key`) needs only sign-in, so a member who lost `jobs.start` can still take it back. A cloud tag can't be set as a default in Diagnostics, and the maintenance assistant treats Ollama with a cloud tag as a cloud engine (per-provider consent).
- **Uploads and deletes are `local_only()`** (the Quick translate screenshot read, `POST /api/translate/read-image` and its price check: a picture is decoded on the PC and sent to a vision engine, so a remote device can still paste typed text but not a picture; the yt-dlp URL download `POST /api/media/dramas/{id}/download-url` (until redirect-validated URL guards and per-user job/bandwidth caps exist, repo-work items 4 and 5; then `media.import_url`) (it runs yt-dlp with every default extractor except `generic`, and fetches a plain direct media link itself with every redirect hop re-validated, pinned and byte/time-capped; what remains is that yt-dlp's site-specific extractors still do their own redirects and DNS without our guard, which is why the route stays PC-only), novel OCR, `DELETE /api/dramas/{id}`, discover title delete, `DELETE /api/translate/history`, and the PC-only deletes: remove audio/video, remove raw novel text, delete a translation version, series character, preset or voice-bank entry, and the learned-style reset `POST /api/review-extras/dramas/{id}/style/reset`, which wipes a series-wide or library-wide learned profile, and its undo `POST /api/review-extras/dramas/{id}/style/restore`, which brings back one of the last `db.STYLE_HISTORY_KEEP` (5) profiles a learn or reset replaced), per repo-work item 7. Line-level deletes (glossary term, note, restructure line delete) are ordinary edits: `lines.edit`.
- **Admin uploads from away are `media.upload`** (owner decision 2026-10-21, "Part A"): media upload and upload-and-transcribe (`media.upload + jobs.start`), subtitle import preview and apply, novel attach-text and attach-epub, the raw novel and English reference (file and pasted text), comic pages and the cover. `media.upload` comes only from the admin flag, like `admin.*`, and is never grantable to a member (`auth_service.ADMIN_ONLY_PERMISSIONS`). At the PC it always holds. Away from the PC (the household listener, or a non-loopback request on the old single-listener sign-in setup) `api.remote_uploads.away_principal` drops it unless Developer Mode is on and Settings > Developer Mode > Allow uploads from away was turned on in the last 7 days (`settings_service.remote_uploads_on`); `/api/auth/me` reports the same, so the upload controls show only then. `RemoteUploadGate` refuses these routes before the body is read when the caller lacks it, and holds an upload from away to the Settings upload limit (Content-Length checked, chunked refused, the body counted). Ownership is the usual write check (an admin away from the PC changes their own, PC-made and shared items, not another member's private ones). Upload-and-transcribe applies the run route's checks (`transcribe_routes.check_run_allowed`): a request-supplied `tesseract_cmd` is refused away from the PC, Groq needs `engines.paid`, and models are not downloaded from away. Link downloads, attach-from-sources, lncrawl, novel OCR and every delete stay `local_only()`.
- **"Fill from link" is `local_only()`**: `POST /api/media-link/probe`, `POST /api/dramas/{id}/link-details/probe` and `/apply`, and `GET`/`POST /api/library/link-scan` read a link with yt-dlp (metadata only) or a Sources adapter on the PC's own connection, for the same reason as the URL download.
- **Synchronous LLM calls are capped** by `api/llm_slots.py` (2 server-wide, 1 per caller, 429 `rate_limited` when busy): the Reader LLM tools, `lines/.../retry-blocked`, `POST /api/translate`, `line-ai` improve/explain/alternatives/grammar, Step 99's `stronger-engine/.../try`, `lines/.../shorten-overlong`, `POST /api/discover/translate-query`, `POST /api/metadata/dramas/{id}/romanize-credits`, `POST /api/metadata/dramas/{id}/research` and `review-extras/.../style/learn`.
- **Settings writes and source pacing/proxy/cookie config are `local_only()`** (`POST /api/settings` (toggles and the persisted preferences, including the Tesseract path, the offline Whisper folder, the yt-dlp cookies browser/file path and the upload size limit `max_upload_mb`), key writes, endpoint URL writes (`/api/settings/endpoints/{name}`, same key-write gate), notification channel set/clear/test (Step 44; set/clear also use the key-write gate), the Step 36 engine-routing writes (`/api/settings/engine-routing/capabilities/{capability}` and the per-engine Test, which spends a tiny amount with the key saved on the PC; reading the routing is `admin.settings`, engine names, booleans and short redacted text only), `POST /api/sources/settings`); other sources administration (enable, adult toggle, extension-only marker, health reset, cache clear, profile rollback, attempts log, settings/profiles read) is `admin.settings`. `GET /api/settings` (`admin.settings`) returns the three path preferences (Whisper folder, Tesseract program, cookies.txt file) only to the PC itself; any other caller gets `""` for each and a `<name>_configured` boolean (security review of PR #439).
- **Source domain lists** (sources that move between domains, e.g. xbanxia and ToonKor): every `/api/source-domains*` route is `local_only()`, reads included. The list decides where source requests go, so setting it from another device would be the same SSRF/exfiltration pivot as the proxy URL. The list and proposals return **host names** with a port only when it isn't 443 (`toonkor1.org`, `toonkor1.org:8443`), a deliberate, PC-only exception to "no fetched URLs": the owner has to see what a proposal would switch to before confirming it. Never a scheme, path or query. Which hosts are contacted: the listed domains, plus any redirect target the ordinary transport follows from them (every hop public-address checked, Cookie/Authorization dropped on a host change). A result that ended on an unlisted host, or moved from https to http, is never used as content or cached under the listed URL; that domain counts as failed. If that final URL is https and its page passes the adapter's `verify_site`, its host becomes a pending proposal (at most 5 per source, a dismissed host never returns); no extra request is made to find it. Confirmation only adds a host to the list and makes it the remembered last good domain; it does not control the transport's redirects. A search POST (xbanxia's `searchkey`) that ends on another host counts as failed, but a 307/308 may already have re-sent its form there. The household listener gets none of it (403 like every `local_only()` route).
- **Web-search fallback** (item 114, off by default): `GET /api/web-search/status` and `POST /api/web-search/search` are `library.read`, the same as the title search they back up (`POST /api/sources/search`): the query goes only to the owner's own SearXNG server, set at the PC, and the reply is at most 20 links (title, snippet, domain, http(s) URL). The app never fetches a result page; the React "Use this link" button only fills the paste-a-link box, so any fetch goes through that flow's own public-address guard (`sources_url_service.check_public_url`). `status` returns only on/off, never the address. `GET/POST /api/web-search/config` and `POST /api/web-search/test` are `local_only()`; changing the address also takes the endpoint-URL gate (`_require_local_admin`) and `confirm: true`. The address is http(s) only with no user name, query or fragment; loopback and LAN are allowed, but link-local, multicast, reserved and unspecified addresses and Baihe's own loopback ports are refused at call time (not pinned to the connection; the DNS lookup relies on the OS resolver's timeout). Requests have `timeout=`, no redirects, no proxy, a 2 MB / 15 s response cap, per-caller limits (the signed-in user, else the client address: one search at a time and 4 a minute) inside app-wide ones (3 at once, 10 a minute; 409 busy / 429), so a loop cannot get the owner's SearXNG blocked or keep web search busy for everyone; the PC-only test has its own lock and bucket; errors are fixed text.
- **Jellyfin connector** (Step 39, off by default): every `/api/jellyfin/*` route is `local_only()`: the settings hold the server address and an API key, the scan reads another server's library, and a send writes files outside the drama folder. Setting or clearing the key, and changing the server address (it moves where the key goes, like the engine endpoint URLs), also take the engine-key gate (`_require_local_admin`) and `confirm: true`; the key lives in `.env` (`BAIHE_JELLYFIN_API_KEY`), is sent only as the `Authorization: MediaBrowser Token=...` header and is never returned (`key_configured` only). The server address is http(s) only, with no user name, query or fragment. Loopback and LAN addresses are allowed (Jellyfin usually runs there), but link-local, multicast, reserved and unspecified addresses, and Baihe's own ports on loopback (8600/`BAIHE_API_PORT`, 8756), are refused at call time (the check is not pinned to the connection: the address is the owner's own, gated setting; its DNS lookup relies on the OS resolver's timeout, while the HTTP requests have their own). Requests have `timeout=`, no redirects, no proxy and a 20 MB / 60 s response cap, and errors are fixed text (no URL, path or key). A send writes only inside the configured library folder (a path Jellyfin reports is checked with `realpath`, the item is matched by id), through an exclusively created temp file re-checked before the rename, copies (never hard-links) a video, checks every destination before writing any, and never overwrites a file unless `overwrite: true`.
- **Saved manga** (chapters saved as CBZ): the save folder is a path on the PC, so reading it, picking it and opening it in the file manager (`/api/saved-comics/folder*`) are `local_only()`. Reading what was saved is `library.read` (the series, chapter and page lists, named by folder and file names only, never a path) and `media.stream` (a page image). Every name is one existing path component under the save folder, and the resolved file must still be inside it.
- **Settings writes and source pacing/proxy/cookie config are `local_only()`** (`POST /api/settings` (toggles and the persisted preferences, including the Tesseract path, the offline Whisper folder, the yt-dlp cookies browser/file path and the upload size limit `max_upload_mb`), key writes, endpoint URL writes (`/api/settings/endpoints/{name}`, same key-write gate), notification channel set/clear/test and which events are pushed (`POST /api/settings/notifications/categories`) (Step 44; set/clear also use the key-write gate), `POST /api/sources/settings`); other sources administration (enable, adult toggle, extension-only marker, health reset, cache clear, profile rollback, attempts log, settings/profiles read) is `admin.settings`. `GET /api/settings` (`admin.settings`) returns the three path preferences (Whisper folder, Tesseract program, cookies.txt file) only to the PC itself; any other caller gets `""` for each and a `<name>_configured` boolean (security review of PR #439).
- **Past-cost re-cost** (`/api/settings/usage-recost`): the preview is `admin.settings` (numbers and model ids, writes nothing); apply and undo are `local_only()` because they rewrite stored spend figures that the monthly cap and dashboard read. Apply needs `confirm: true`, touches only the reviewed list of mis-costed models, answers 409 if the previewed count or set of rows no longer matches, and keeps each row's first original cost in `usage_log.estimated_cost_usd_before_recost` for undo.
- **Monthly counter reset** (`/api/settings/month-counter/reset` and `/undo`): `local_only()` because they change what the monthly spending cap counts. Reset writes one app setting, `monthly_spend_reset_at` (UTC time, now); Undo clears it. No usage rows are changed, and a reset from an earlier month stops applying when a new month starts. The status (full month, counted toward the cap, reset time) is part of the `admin.settings` read `GET /api/settings`; responses carry numbers and a timestamp only.
- **Experimental transcription settings** (`/api/settings/asr-options`, Step 103): reading them is `admin.settings`, saving is `local_only()`. See `docs/asr-experiments.md`.
- **Drama cover art** (react-misc-parity): the upload `POST /api/dramas/{id}/cover` is `media.upload` (admin uploads, above); it takes PNG/JPEG/WebP only (decoded by Pillow, not the declared type), at most 10 MB and 25 megapixels, and re-encodes the pixels so EXIF/XMP/ICC and text chunks are dropped. `GET /api/dramas/{id}/cover` is `library.read` and serves only a stored `cover.<png|jpg|jpeg|webp>` inside the drama folder, with `nosniff` and a `sandbox` CSP. Romanize credits is `admin.library` (it writes drama metadata) plus `require_engines_allowed` for the engine that runs. Using the chapters imported in Sources as narration text (`attach-from-sources`) is `local_only()`, like the other novel attaches.
- **The library-wide learned style is PC-only to change** (judgement call, 2026-09-29, security review of PR #444). A drama with no series learns into, and pauses, the `global` style profile, which `adaptive_style.profile_to_prompt_block` injects into every drama's future translate prompts, and learn feeds every drama's recorded edits to the LLM. So `review-extras/.../style/learn` (`jobs.start`) and `style/apply` (`lines.edit`) answer 403 to a remote caller when the drama's scope is `global` (the handler checks `is_local_request`; the route table above still lists their declared permission). A series profile only shapes that series, so a household user with the route's permission may still learn or pause it remotely. Every learn and reset keeps the profile it replaces (`db.replace_style_profile`, last 5 per scope), and the PC-only `style/restore` brings one back, so a bad remote learn on a series profile is undoable.
- **A learned style profile reaches only admins, the PC owner and its own learner.** A profile is distilled from every edit its learner could see, which for an admin or the PC owner includes other members' private edits, and is stored per scope (series or global), not per user. The owner decided (2026-10-14) that it reaches only the owner and admins; a member also gets a profile they learned themselves, since it is built only from edits they could see and so leaks nothing. A learn records the learner's user id on the profile, and `ownership_service.sees_learned_style` lets a profile reach a principal only when they see everything (auth off, the PC owner, an admin) or learned it themselves. Everyone else gets no `profile` or `history` from `GET .../style` and `GET .../tendencies`, can't pause it (404), and has it left out of every translate prompt they start (`workspace_job_service.build_run_style_context`; job threads get the starter's principal captured at start). A member's Learn over a profile they can't see is refused (409) before the LLM call, so it never silently replaces someone else's profile; a pause stays in place across a re-learn. The edit counts are unchanged. A profile from before this rule names no learner, so it reaches only those who see everything.
- **Drama-level metadata and library catalogue writes** (create drama, drama metadata, autofill apply, preset/voice rename, save translate settings as a preset (replacing an existing one is PC-only: 403 remotely), discover create/seed/import) are `admin.library`; per-drama stage config (source, transcribe, applying a workflow tier) and flags/glossary/characters (including adding and editing a series' people; removing one stays PC-only) are `lines.edit`.
- **Glossary import** (`POST /api/glossary/dramas/{id}/import`, parity T03): the body is the file's text, parsed and never stored as a file, so adding new terms is `lines.edit` from anywhere (existing terms are skipped). Replacing existing terms (`overwrite_existing: true`, also `confirm: true`) is the planned LAN exception, but there is no LAN zone yet (`api/auth.py` knows only PC vs not-PC), so until network zones exist the handler refuses it with a 403 unless the request is direct loopback (`_auth_enabled and not is_local_request`, as for preset overwrite). The React panel hides the file picker and the replace checkbox off the PC (`usePcOnly`); pasting text stays. The CSV export (`GET .../export.csv`, `library.read`) prefixes a cell starting with `=`, `+`, `-`, `@`, tab or CR with `'` so a spreadsheet does not run it as a formula, and the import drops that one `'` again.
- **Media bytes** (`artifacts/.../{kind}`, dub track, and a voice-bank entry's clip `GET /api/library/voice-bank/{entry_id}/audio` (household-wide like the voice bank; served only when the clip resolves inside the voice-bank folder, symlinks refused, audio types only, generic file name, nosniff)) are `media.stream`; subtitle/EPUB/ASS text exports are `lines.read`. Any other route that returns line text needs `lines.read` on top of its own permission (`require_permission(a, b)` needs both): the library line search and a title's characters with their sample lines are `library.read + lines.read`, the speech coverage result (raw transcript text in its gaps) is `library.read + lines.read`, and the review history snapshot, version compare, TM suggestions and the stronger-engine try are `review.use + lines.read`. `/api/jobs` reads are `library.read`, and each caller sees only the jobs `ownership_service.can_see_job` allows (a title's jobs follow the title's visibility, any other job only its starter; admins see all).
