## 3. Security model

**ToS/robots reality (verified).** `ladder.check_terms` is a `pass` (`ladder.py:359-362`), deactivated 2026-09-27 by explicit user decision (Step 90); its tests are skipped (`tests/test_sources_workflows.py:615-690`). There is no robots.txt fetcher or parser, only static `host_min_interval` crawl-delays. Recorded terms data still exists: `site_terms.SITE_TERMS` (5 sites) and each adapter's capability `terms` block. API rule: every fetch service calls `ladder.check_terms(...)` at the service boundary (no router-only gate), so re-enabling that one function covers the API. Show recorded findings as informational and never label anything "permitted" (UNKNOWN is not PERMITTED, `site_terms.py:12-14`). Needs the user's answer (Q1).

**Sign-in and cookies.** Session state never crosses the API. The profile is `<library>/profiles/<key>/` (`store.py:78-91`) and `auth_browser` never reads cookies (`auth_browser.py:21-24`). The API returns only `has_saved_signin` bools and the `LoginCheck` message and facts; free text (`lines`, `detail`) must be scrubbed of paths (`ladder.py:161-166` redacts secrets only; Playwright launch errors contain the profile path, HYP). `open` and `forget` are local-only (S-6). Implicit hazard: `generic_import.fetch_page` switches to the signed-in tier automatically when a profile exists (`generic_import.py:325`), so any remote-triggered URL preview or import for a signed-in domain would read pages as the owner's account. Give services an explicit `allow_signed_in` argument that the router sets false for non-local requests, or decide otherwise (Q2); it needs a small edit to `generic_import.fetch_page`, owned by S-5. `cookies_browser` (yt-dlp reading the PC's browser cookies) and `cookies_file` (a server path) exist only in Streamlit session state; the API accepts neither, for downloads (`front_door.py:161-185`, `video_download.py:33-45`) or live capture. A persisted server-side cookie setting is admin-only (D5) and not in these slices.

**SSRF.** Reuse the `metadata_service` pattern (IP validation on every hop, pin to the validated IP, keep SNI and cert checks, `timeout=`, capped bytes, fixed error text) through D-0. Known holes if a raw user URL reaches them:
- `page_fetch.fetch_static` uses `requests.get(url)` with redirects and no IP check (`page_fetch.py:91`); used by `navigator` (l.20) and `smart_fetch`.
- `SourceClient._requests_transport` uses `allow_redirects=True` and no IP check (`http.py:141`).
- `page_fetch._rendered_page` and `fetch_with_profile` run `page.goto(url)` with no scheme or IP restriction (HYP: `file://` and internal IPs reachable from Chromium; no pinning possible in a browser).
- **Confirmed blind SSRF in existing code:** adapter URL patterns are unanchored `re.search` (`bilibili\.com/video/...` and `b23\.tv/`, `bilibili.py:47-51`; `_VIDEO_URL`, `front_door.py:26-29, 79`). `http://169.254.169.254/?b23.tv/` matches; `normalize_url` then does `"b23.tv" in url` and calls `client.request("HEAD", url)` with redirects (`bilibili.py:184-185, 168-173`), and the same URL goes to yt-dlp.
- `resolve_stream_url` (`live_translate.py:109-180`) and ffmpeg (`start_segment_capture`, l.198) fetch client-supplied URLs with their own DNS.
Rules: user-supplied URLs go through D-0 for the fetch and use no rendered or auth tier for non-local requests; adapter routing requires the URL host to match the adapter's known hosts, not a substring; API inputs to adapters are ids, never URLs; video and Live URLs get scheme and public-host validation plus an allowlist of platform domains; a yt-dlp and ffmpeg TOCTOU remains (accept it or restrict to local, Q3). `metadata_service._pinned_get` sets `trust_env=False` (l.172), ignoring `http_proxy_url` and environment proxies (HYP: in a proxy-only network D-0 fetches fail).

**Rate limits and concurrency.** Per-source pacing and a semaphore live in-process (`_source_state`, `http.py:194-208`); an API process and a Streamlit process each pace separately, so running both doubles the request rate to a source. A sync endpoint blocked in `_wait_turn` ties up a threadpool worker, hence jobs for anything paced. Add a per-client cap: at most one running Sources or Discover network job per kind (fixed ids), 429 `rate_limited` for a burst of job starts, and caps on URL counts, chapter counts and page size. A remote device may: read catalog and status, search (paced on the host IP), preview. It may not, until D5/D6 exist: sign in or forget sign-in, change proxy or pacing floors, use signed-in reads, use paid engines without a permission, or set cookies.

## 4. Live capture (separate proposal)

- **L-1, polling only (thin; unblocked once policy is set).** `POST /api/live/sessions {url, source_language, whisper_size, segment_seconds, overlap_seconds, engine, max_minutes}` returns `{session_id}`: checks the platform allowlist and public host, resolves the key server-side, starts a job under a per-session id (not `live_capture`) with `gpu_touching=True`, and hard-stops after `max_minutes` (`process_chunk` calls the engine unbounded, `live_translate.py:437-440`; no spend-cap check found, HYP). `POST /api/live/sessions/{id}/stop` does `live_translate.bump_generation` then `request_cancel`, or `cancel_queued` if queued (bump first, `live_tab.py:110-127`). `GET /api/live/sessions/{id}?after=N` returns status, message and `cues[N:]`, never a traceback (the job dict holds one; `JobRecord` does not). Use a per-session `tempfile.mkdtemp` directory removed on finish: the Streamlit tab uses a fixed `tempfile.gettempdir()/baihe_live_capture` (`live_tab.py:95`) and `run_live_job` never clears it at start, so stale `chunk_*.wav` files from an earlier run are processed as new (`live_translate.py:496-510, 226-235`; HYP from reading), and two sessions (one per process) would collide.
- **L-2, optional SSE.** `GET /api/live/sessions/{id}/events`, an async generator over an in-memory poll of `background_jobs.get_status(id)["result"]`. `event: cue` with `id: <index>` for `cues[last:]`; support `Last-Event-ID` (the list only grows; a new session has a new id); `:` heartbeat every 15s; `event: end` on terminal status; cap concurrent streams (about 4); `X-Accel-Buffering: no` and `Cache-Control: no-cache`. Fit with `background_jobs`: read-only over in-memory state, no persistence, lost on restart; `job_records` carries no result so a session started in another process is invisible. Same-origin GET works with the current CORS (`allow_methods=["GET"]`, `server.py:76-81`). Unknown: whether the Vite dev proxy and any remote-access proxy pass streaming unbuffered; verify by hand. If they buffer, L-1 polling is the fallback (what `useJob` does).

## 5. Rules from CLAUDE.md that apply, with specific risks

- **No AI results by position:** `bulk_import.extract_listing_entries_llm` and `adaptive` map picks to block, link or image ids (ok); `live_translate.process_chunk` translates one text at a time (ok); `dedupe_content` is positional and not touched.
- **No key in a URL, log or error:** `ladder._browser_outcome` redacts only secrets, not paths (`ladder.py:161-166`); `run_import_job` stores `f"{reason}: {e}"` (`pipeline.py:157-161`); `LiveCaptureError` text embeds the yt-dlp exception (`live_translate.py:154-171`); the `access_attempts.url` column stores pasted URLs with their query strings; `suggestion["source_url"] = url` (`metadata_service.py:255`) echoes user input. Every response text goes through `redact_secrets` plus path and query stripping.
- **Every HTTP call has `timeout=`:** `tests/test_static_analysis.py:531-539` already scans `services/` and `api/` but matches only `requests.<verb>` and `session.request` (l.459-461), so `_pinned_get`'s `session.get` slips through the pattern (it does pass `timeout`). Extend the checker for `session.get/post`. yt-dlp calls (`live_translate.py:127-141`, `bilibili.py:164-166`) set no explicit `socket_timeout` (HYP: its default applies).
- **Background job must not overwrite other work:** no `save_lines`; import writes files and pages. Race risks: `raw_novel_context.txt` append (`pipeline.py:75-79`), `create_page` index (`pipeline.py:45`), and the delete-during-import gap above.
- **CLI/UI parity:** `cli.py` has no sources, discover or live command (HYP; not read in full). Low parity cost, but state it in slice notes.
- **Optional dependencies:** register in `diagnostics.OPTIONAL_DEPENDENCIES` if any slice adds one (none expected).
- **`FILE_ORGANIZATION.md`:** update in each slice that adds a service or router, plus the "14 sites" drift.
