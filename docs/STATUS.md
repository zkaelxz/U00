## Where the app is

What works:
- React + FastAPI is the only app: `python -m api` serves the API and the built React app (`start.bat` runs it). Streamlit is gone (`pre-streamlit-removal` tag, `legacy/streamlit` branch).
- Remote access: Google sign-in, ownership, deny-by-default permissions, the D5 admin and household listeners, private-by-default sharing with an admin Sharing screen and the admin audit log are merged. `docs/route-permissions.md` is enforced by `tests/test_api_permissions.py`. Sign-in is optional and off by default (`BAIHE_API_AUTH`); with it off only direct loopback requests are served. The Caddy template (`deploy/caddy/`), the Caddy helper (`installer/caddy`), owner-run `enable-remote` / `disable-remote` / `status` and the certificate/DDNS banner are in the repo. Don't expose the API beyond loopback until the owner's LAN and router checks are done. What is exposed and what is deliberately not defended: [`threat-model.md`](threat-model.md).
- Windows installer with hash-pinned wheels, the boot service with its stored port (`service.py set-port`; `BAIHE_API_PORT` only on a fresh install), the Setup lock, auto-backups (2 daily and 2 weekly per library), one person's export and import from a backup file (PC only; tracked series, the voice bank, settings and other profiles' data don't travel), Library tools with five tabs (Organize, Activity, Backup, Storage, Data folder) and a restorable Trash, sources.db inside backups and restores (so tracked series and extension-only markers survive), and a library temp folder swept at startup and left out of backups.
- Transcription: Whisper (default `large-v3` on CPU and GPU, `default_whisper_size()`; `large-v3-turbo` is the fast option; medium and below are hidden from the pickers except Live, `whisper_models.selectable_whisper_sizes`), the opt-in Qwen3-ASR backend with its own speech detection and automatic language, forced alignment, re-timing of existing lines with the Qwen3 aligner, word timings stored per line and used by every split, per-line spoken language (mixed-language titles), hallucination guards (silence threshold off by default), time estimates from your own runs, the optional ASMR voice detector, "Check timing", "Transcribe this gap", bulk re-transcribe, and a waveform timeline in Review. Measurements: `docs/asr-experiments.md`.
- Whisper on the GPU uses the best compute type the card supports (float16 first; int8_float32 on a GTX 10xx, which has no float16) instead of always asking for float16 and dropping to the CPU on older cards.
- Ollama model pickers (Translate and Live) list the models pulled on the server (`GET /api/tags`, the same request as the reachability check and cached as long, embedding-only models left out) next to the built-in tags; Live accepts a pulled tag instead of refusing anything outside the built-in list.
- Ollama address: every feature reads it through `settings_service.ollama_url()`, which adds a missing `http://`, drops a trailing `/` and the `/api` of an address on Ollama's own port 11434 (a reverse proxy's `/api` prefix is kept), and falls back to `http://localhost:11434`; Settings saves "localhost:11434" instead of refusing it.
- Diagnostics > Recommended installs has an **Install all** button: GPU PyTorch first, then every other missing package together, so nothing that needs torch pulls the CPU build. Tokens and separate programs (Ollama, the Tesseract binary) stay manual.
- The install plan blocks (not just warns about) an install that would downgrade a package below the minimum the app's requirements ask for, so PaddleOCR (PaddleX caps numpy under 2.5.4) can't be installed over the core app; a downgrade that stays above the minimum is still a risk the owner can accept. The same plan refuses an install that would replace the installed PyTorch or, on an NVIDIA PC, pull PyTorch in from PyPI before GPU PyTorch is set up (demucs brought the CPU build that way), and GPU PyTorch setup dry-runs its dependency step first and refuses one that would downgrade a package the app needs. pip's own refusals are named: the packages in a conflict, a package with no release for this Python (refused instead of queued for the next start), or no connection to the index; every block reason is shown, not just the first.
- Speaker detection stays on the CPU when the installed PyTorch has no kernels for the card (a CUDA 12.8 build on a V100 or other compute < 7.5 card, whose cuDNN 9.19 refuses it) instead of failing on the GPU and then crashing; the log names Diagnostics > GPU PyTorch, which installs the CUDA 12.6 build for those cards.
