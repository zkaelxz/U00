# User guide: reader and library

Part of the [user guide](user-guide.md).

## Reader & Library

### Interactive Reader

Raw and translated text side by side, for proofing and language learning.
- **Word segmentation**: jieba (Chinese), sudachipy (Japanese), kiwipiepy (Korean). Install what you need: `pip install jieba pypinyin` / `pip install sudachipy sudachidict_core pykakasi` / `pip install kiwipiepy`.
- **Ruby annotations**: pinyin over Chinese, furigana over Japanese kanji (Korean is skipped).
- **Click-to-define**: Chinese uses a local CC-CEDICT lookup (downloaded once, then offline). Japanese, Korean and unknown Chinese words use an LLM definition and need an API key.
- **Pagination** keeps big chapters light. Follow-along playback highlights the spoken line using the Reader's own embedded clip. Reading progress saves when you change pages; playback position is stored separately.
- **Settings**: text size, line spacing, width, font, lines per page and a Reader theme (Match app, Light, Sepia, Dark), separate from the app theme in the header.
- **Spoiler-free mode** (Settings, on by default) limits every AI feature (character lookups, recaps, relationship maps, the wiki) to the page you have reached.
- **Universe wiki**: an encyclopedia built as you read (characters, places, sects, artifacts, events), updated on re-extraction and exportable as Markdown.
- **Story tools**: who is this character, relationship map (Mermaid), spoiler-safe recap, explain an idiom or reference; **Ask about the story** answers from the lines loaded so far (an answer the engine blocked or left empty shows as an error). These need an API key.
- **Line tools** (in Review): "Why this?", "Improve translation" (feeds the adaptive style profile) and "Re-transcribe this line" (re-runs Whisper on that line's audio only).
- **Vocabulary export**: looked-up words export as Anki-importable CSV or a `.apkg` deck (the `.apkg` needs `genanki`).

### Library

- **Continue shelf** with cover art and progress; reading history (clearable).
- **Metadata**: cover, genre, publication status, chapter count, custom tags, private notes, reading/listening time estimates.
- **Stream / release date**: set it in a title's Media > Details (empty = unknown; Baihe never guesses it from the date added). The Library can sort by it (titles without a date last) and **Group by** series, media type or status, with each series' titles oldest first so you can watch in order; a series page has its own **Sort titles by**, and both remember your choice in this browser.
- **Filters**: the Voice actor filter lists titles credited with exactly the picked name ("Li" no longer also lists "Lin Yu"). Removing a title's audio or video that another program holds open, or that Baihe's account may not delete, says so and keeps that file on the title.
- **Dashboard**: totals, translated lines, API calls, estimated spend, cache-hit rate, per-drama costs.
- **Series**: dramas sharing a glossary or characters get a consolidated view. Each series has its own page (`#/series/<id>`), opened from **Series** on the Library page or from "Open series page" in a title's Glossary. It has four tabs: **Titles** (every title in the series with its media type and line count; each opens the title), **Defaults** (below), **Glossary tools** (the term count, a link to the glossary and series instructions, and **Copy terms from another series**: pick a series, see a preview such as "2 new terms will be added, 1 is already there and is skipped", then copy. A term the series already has, with the same original text ignoring case and width, is skipped and keeps its own translation and notes; nothing is removed from the other series, another person's private series is never offered, and a series with more than 2,000 terms can't be copied in one go) and **Settings** (**Rename series**, refused when another series you can see has the same name ignoring case; **Delete series…**, PC only, first lists what goes and what stays: the titles are kept and become "No series", while the series glossary, series characters, instructions, translation memory, dismissed suggestions and learned style profile are deleted with it. A series holding anything needs DELETE typed; an empty one a second press. It is refused while a job runs for any of its titles, and no files are touched). A title with no series can't hold glossary terms: pick a series, or "New series…", in its Glossary first. The Series page's **Defaults** tab holds default title settings (translation engine, the Translate toggles and the Transcribe tuning; never API keys, Groq transcription or Thinking, which only someone allowed to use paid engines may switch on for a title): a new title in the series starts with them, a title moved into it gets them only for settings it has no value for, and **Apply to all titles in this series** previews, per title, what would change before writing it ("Only fill settings a title hasn't changed" by default, where a value equal to the app's default counts as unchanged, or "Overwrite every title's settings"); it changes only titles you may edit and is refused while a job runs for any title in the series. The New title, Edit details and Glossary series pickers now list every series you can see, one-title and empty ones included.
- **Search and bulk actions**: a global search over every drama's original and translated lines; bulk status, delete (typed confirm) and translate (skips dramas without a key, lines, or already running).
- **Library tools** (page): export all translated titles as a zip (Organize tab), per-drama export package (with a manifest of what was included), translation setting profiles (pick one on New title; edit, rename or make one the default here), voice bank, series, costs and reading history. It has five tabs: Organize, Activity, Backup (Back up with the library, database only and just your stuff, then Restore, then the automatic backups (schedule) and their copies), Storage (how much space is used and free on the drive, the cleanup scan with quality presets (Archival, Balanced, Minimal; only regenerable files are removed), unused voice clips, the Trash and temp files) and Data folder (what is using space in Baihe's data folder; the program's own files sit in one closed "Program files (protected)" row). Away from the PC, Backup, Storage and Data folder are left out. The page opens on the tab you used last. The Data folder view never follows a link or junction when it counts a folder: the folder's size is what is inside it, and the folders the links lead to are shown apart as "Linked folder, stored elsewhere" with their own size, and as "plus N in linked folders" next to the total. Those are not counted in the folder's size or percentage, and a link, or a folder holding one, can't be moved to Trash from here. In library > dramas each title also shows its size by kind: originals (source video and audio, uploaded and replaced media, page scans, the novel files), raw transcripts, line history (the snapshots in the database) and rebuildable files (what the storage presets may remove).
- **Backup and restore**: a database-only snapshot or a full zip with media, streamed to disk; restore validates the zip first and needs a typed confirm. Signed-in browser sessions from Sources are not included. Automatic backups are opt-in and are set up on Library tools > Backup (the schedule, folder, "Back up now" and the copies sit there next to Restore); Settings has one short card with the current schedule and a "Manage backups" link. Before each automatic backup Baihe checks the backup drive: with less free space than 1.2 times the expected copy (the last copy's size, or the library's for the first one) the run is skipped, the settings page shows a warning, no old copy is deleted, and it is tried again a day later. See `docs/runbook.md` section 3. Baihe records which version last opened your library and refuses to start if that was a newer version than the one you are running, since an older build could misread the newer data. Upgrade Baihe, or restore a backup from the backups folder in your Baihe data folder. The database inside a backup (and the per-person backup) holds each title's source link as it was imported, query included, which can carry a site's sign-in or download token; treat backup files as private. A backup's `manifest.json`, the export zip and support reports never carry it. A backup holds the sign-in accounts (no passwords, sessions or device tokens). A rebuilt PC gets those accounts back only if the backup holds them and the library you restore into had no accounts yet; a library that already has accounts keeps its own: each restored title then goes to the account with the same email (or to the PC owner when there is none), private titles stay private, the restore summary says how many titles changed owner, and the backup's followed live channels pass to the PC owner with automatic checks off. Restoring one title from an automatic backup copy matches its owner the same way (by email, or the PC owner when there is no match or the copy holds no accounts), keeps a private title private, and the result says how many owners changed. Media of titles added since a database-only backup, and folders that backup lacks, stay in the previous library beside the library folder; Storage > Previous library shows its size and deletes it. Reset library keeps a copy of the last library there too.
- **Keep original files** (a title's Media > Add media tab): when on, the storage scan presets never remove that title's source audio and video, uploaded files, raw novel text, raw transcripts or page scans; the export zip puts them in the title's `originals/` folder; and deleting an item from Trash that came from the title's folder says so in the confirmation. They keep using disk space. Changing it needs the same permission as editing the title's details.
- **Open original page**: every page shows the title's source link without its `?query` part, which can hold a download token. On the main PC the button opens the link exactly as it was imported or typed instead (a video link may need its `?v=`); away from the PC it opens the cleaned link. The full link is never sent to household or remote accounts.
- **Translation versions**: every translation run is saved with its engine and model; compare versions side by side and activate one (the current one is snapshotted first).
- **Undo**: line snapshots are taken before risky edits (a force re-translate, an applied merge, a re-transcribe, a shorten, a cleanup, activating a version); restore from Records → Line history (the 10 most recent are kept; all but the newest 3 are stored compressed, and they restore the same way).
- **Drama IDs skip numbers after a deletion, on purpose.** Lines, glossaries and versions reference a drama by id, so reusing one could re-attach stale rows or conflict with an older backup. The Library shows a separate sequential **#** column.

### Discover and titles

- Discover has two tabs, **Find a title** and **Add titles**; the Catalogue tab (a search of titles you've saved locally, with "Load starter titles" and "Import to library") is currently hidden. Discover > "Find a title" > "Find on official platforms" builds site-scoped search links across known platforms. It deliberately never asks a model to suggest titles, since a model invents plausible ones.
- Baihehub search translates your query to Chinese first and is best effort; if it comes back empty you get a link to its own search page.
- Add a title by URL (a listing page), by hand, or by **bulk import** of up to 10 tag/ranking listing pages (title, author, tags, audio-drama flag; never content). A review table always comes before saving, with a "paste the page text" fallback for JS-only sites.
- **Known sites** (`known_sites.py`): a curated directory of official platforms for Chinese baihe, Korean GL and Japanese yuri, browsable in Discover's "Open a site or explain a page". No aggregator or scanlation sites.
- "Open a site or explain a page" opens a site in a new tab (most sites refuse to be shown inside another page), or has the PC read a public page in a language you don't read and write step-by-step help for it.

### Manhua and Scanlate

Detection is heuristic and surfaced for review. A speech bubble is an enclosed light region that doesn't touch the page edge; panels are found by gutter analysis in manga reading order; long webtoon strips are sliced at whitespace gaps with a small overlap; regions are classified (bubble, narration, sign, SFX, thought) and font style is sampled.

Comics are translated on the Comic page, not in the Workspace's Translate, Review, Dub and Export stages (those show "Comics are translated in Scanlate" with an **Open in Scanlate** button). The page's **Translate** button opens the Scanlate panel.
1. Upload page images or PDFs (PC only; optionally "Slice tall strips").
2. Pick the engine and, when the title has chapters, this chapter or all chapters. Advanced > **Text detector**: Auto (the ML detector `ogkalu/comic-text-and-bubble-detector` once it is downloaded, else the free OpenCV heuristic), OpenCV heuristic, or ML model (downloads once; needs `transformers` and `huggingface_hub`). The OCR backend is the one in Settings > System > Offline, paths and limits > OCR.
3. **Translate all pages** detects, reads, cleans, translates and typesets each page, skipping pages that already have text; **Redo this page…** (beside Translate, on phones too) and **Redo all…** (or **Redo chapter…**) replace a page's text after a confirm. **Translate captions on the art** (off by default) also paints out large lettering drawn on the artwork and sets the English in the same colour and glow, in a regular face when the original strokes are thin (needs PaddleOCR and the LaMa-manga model; about 5 seconds per caption). A caption cut by the page break in **Translate all pages** is translated as one line and the English is split between the two pages.
4. Read the result with the **Typeset pages** view setting, then Export ZIP or PDF. The export follows that setting (off exports the original pages) and says which pages are untranslated.

The Chapters & pages sheet can also list the source's chapters and import one.
Limits: the CV detector misses borderless or irregular bubbles; text is erased with the LaMa-manga model when its weights are downloaded, otherwise with OpenCV's inpainting (weak on patterned backgrounds); text is horizontal only; OCR crops slightly inside the bubble border, so check the source text.

## Metadata & site tools

### Browser extension

A Chrome/Edge extension that sends the page you're reading into Baihe and draws the translation over it. It also reaches pages an adapter can't (`blob:` images, site-unscrambled readers, signed-in pages) because your own browser already did that work. Turn it on in Settings > Integrations > "Browser extension", load `extension/` unpacked (`chrome://extensions` > Developer mode > Load unpacked) and paste the token. It talks only to `127.0.0.1`. Pages of one title are translated one at a time, each with the context of the page that finished just before it: that follows the order captures get their turn, not page order, so a page sent out of order (or racing another) reads the wrong neighbour's context, and one that waits over 30 seconds behind a slow engine is translated without context. Details: [`browser-extension.md`](browser-extension.md). On another computer in the household, make a token under Settings > Sharing and devices, load the same folder, and in the extension options enter the household address and the token.

### Metadata romanization

Credits keep the original script and gain a romanized companion: 一半山川 displays as "Yiban Shanchuan (一半山川)". Personal names are romanized; studios and platforms use their established English name where one exists (晋江文学城 as "JJWXC").

### Fetching from JS-heavy sites

Some sites (baihehub, Fanjiao) build pages with JavaScript, so a plain fetch returns an empty shell. `page_fetch.py` handles it in three layers: it detects an unrendered shell and says so; with the `playwright` package installed (Diagnostics > Packages and installs > Packages, or `pip install playwright`) it re-fetches with a real browser: an installed Chrome or Edge, Playwright's own Chromium, or the program named by the `BAIHE_BROWSER_PATH` system environment variable. No browser download is needed when Chrome or Edge is installed; Diagnostics > Setup shows the package and the browser separately (the browser install is on Packages and installs); and manual paste (copy the page text into the app) always works.
