# User guide

The feature walkthroughs, setup details and troubleshooting that used to sit in the root `README.md`. The README keeps install and start; this page keeps everything else a user needs. Menu paths and button labels were checked against `frontend/src` when this page was split out; the UI changes often, so if a label here is off, the UI wins.

Related docs: [`engine-backends.md`](engine-backends.md) (translation, transcription and dubbing engines), [`asr-experiments.md`](asr-experiments.md) (Whisper model choice), [`browser-extension.md`](browser-extension.md), [`household-access.md`](household-access.md), [`runbook.md`](runbook.md) (restore, certificate).

## Start here

Baihe Studio turns Chinese, Japanese and Korean audio dramas, novels, comics and videos into reviewed English subtitles, and keeps every title in one library on your PC.

1. **Add a key or choose a hosted engine.** Open Settings and add a translation key, or choose Ollama's hosted Gemma (sign in to Ollama).
2. **Add a title.** Use the Add box at the top of the Library (on a phone, the Library's **Add** button or **Find & Add** in the menu): paste a link or choose or drop an audio or video file, and it says what it found and what **Make English subtitles** will do. For a file that transcribes with Whisper, translates and gives you the SRT on the Add page (if a step fails it stops there and says why; a file of the wrong type, or an empty one, is refused before any title is made; if an earlier run is still going there, the new file waits and is put back in the box to start once that run is done; after the upload the PC's queue carries the run on, so it transcribes and translates with the page closed (shown on the Jobs page as Transcribe and Translate), with the translator picked for that run; come back and the page shows where it got to and offers the SRT, and the box remembers the translator for the next run); **Change options** has the translator, source language, title and English variant. **Add only** opens New title with the link, or the file's name and type, filled in (the file itself is chosen again in the title's Transcribe step), and **Add a title by hand** opens an empty New title. A title named from a link, or added from a source page in Find (Sources), also gets an English title beside the original one, from one small request on the engine the browser extension is set up with; if no engine is ready, the cap is used up or the account may not use that engine, the title is made as it was and you can type the English title. Any signed-in account can add a new title from a phone or another device (a member up to 200 titles; an admin can switch it off for a person in People > Rights); uploading a file from away still needs the remote-uploads switch. An admin can also put a title in a series (or make a new series) from away, which is what the glossary needs; the rest of a title's details still change only at the PC.
3. **Transcribe.** Open the title and run Transcribe on its audio or video.
4. **Translate.** Run Translate, then fix lines in Review.
5. **Export.** Download SRT, VTT, ASS or LRC from Export.

Search pages and titles is the box at the top of the page (or Ctrl+K, ⌘+K), and inside a title it also finds that title's lines and opens Review on them; "/" searches the page you are on and "?" lists every key (so does the **Shortcuts** button at the top right where the top bar shows its words, and the ? button where it shows icons; the comic reader's keys are in the list). Backups are on Library tools > Backup, and settings are under Settings. If something fails, Diagnostics checks your setup. Use Report a problem in the app if you get stuck, and read on for the details. The menu docked on the left or right, and not minimized (a minimized one shows icons), lists the pages as words under their group names, with the page you are on highlighted; inside a title, the title's own row under Library is the highlighted one, and in this docked menu (not floating, minimized, top or bottom) **Jobs** shows a quiet 0 until something runs.

## What the app is

- **Folds.** A heading with a small triangle before it opens and closes when clicked; a closed one shows its current value in one line.
- **Pages.** Library, Library tools (with Saved manga), Find & Add (one box for a title's name, which searches your Sources and lists each match with **Add to Library** (one tap: it makes the comic or novel title with its source link; **Chapters** opens the series in Sources to pick chapters), or **Open** and **In your Library** when a title you can see already has that link, with All / Comics / Novels / Videos buttons, or a link, a file or a title made by hand, with Manage sources as a button; the old Discover and Sources links still open), Text, Live, Jobs, Settings, People and access, Diagnostics, and Benchmark Lab and Assistant (both Developer Mode) in the nav, plus each drama's Workspace stages, the Reader and Comic (`frontend/src/pages/`). In a title's stage tabs the underlined, bold tab is the open one; a ✓ marks a finished stage and the blue dot the title's next step.
- **Sources that need the browser** (Fanjiao, Bilibili Manga) can only be read by a real browser render. Until the playwright package and a browser (Chrome, Edge or Playwright's Chromium) are found, their Search and chapter Import stay off and the install notice from Diagnostics > Packages is shown. The browser only runs for requests from the PC: from another device, importing or saving their chapters says to open it at the PC.
- **Access.** `python -m api` serves the built `frontend/dist` at `/`. The PC's own port is loopback-only and needs no login; other household devices can use a separate listener with Google sign-in, which is opt-in and asks Google only for your email address, not your name or picture ([`household-access.md`](household-access.md)). People and access lists its parts down the left (on a phone, one row of tabs): **People**, **Activity** (the Activity log), and at the PC **Remote access** (setup steps, sign-in settings, the public address check and Uploads from away together) and **PC profiles**; away from the PC only People and Activity show. A link such as `#/admin?card=remote` opens the part it names. **People and access > PC profiles** (at the PC): set a PIN and the PC window opens on a "Who's using Baihe?" screen. Guest leaves out every title and series marked private; Owner needs the PIN, and **Switch profile** in the header goes back to Guest. Turning it on can mark all your current titles private in the same step (a switch, off by default, sent with the PIN; it sets the same private flag household members see, and turning profiles off does not undo it). The PIN is 6 to 12 digits; five wrong PINs pause attempts for a minute (a restart does not reset the pause), a restart always comes back to Guest, and a restore keeps this PC's PIN. A lost PIN is cleared with `python -m api clear-pc-pin`. This hides titles from view in the app; it does not lock the files; Guest keeps every owner power (Settings, backups, People and so on), someone who knows a title's direct address can still open it, and it works only for the PC window with sign-in off, which is how the installed app runs. At the main PC, People's **+ Add person** opens a form (email, an optional name, and an "Also allow the browser extension" switch): the person gets the household rights (including playing audio and video) and their first Google sign-in links the account; nobody can sign in before they are added here, the same as `python -m api add-user`. It is not offered away from the PC, and it never makes an admin. Each person in People is one row (name, email and a short status); click it to open their details, fields and buttons. There are no Save buttons: a field saves when you press Enter or leave it, shows **✓ Saved** once the PC has answered, and on a refusal turns red with the reason and keeps what you typed (Esc puts the saved value back). The **Name** field (empty clears it) works for any account, from any device an admin is signed in on. With 8 or more people a **Find a person** box narrows the list and the rights grid. A deactivated member's row also has **Delete…** (press it twice; Deactivate the person first, and an admin account or your own never shows it), from any device an admin is signed in on: the account, its rights, sign-ins, extension tokens and saved key are removed for good and the email can be added again as a new person; their titles and series stay in the library (Sharing shows their owner as "Removed user" until you give them to someone), and the delete goes in the Activity log. A backup of one person's items can't be made for a deleted account, so make it (or give their items to someone) first. Admin accounts and active accounts can't be deleted, and Delete is not offered away from the PC. The form reminds you that, while your Google app is in testing, the same email must also be on its test users list in Google Cloud; the "isn't on this household's list" sign-in message only asks the person to have the PC owner add them, since Google itself turns away an email that is missing from that list. Below the people, **Rights** is one grid: a row per right and a column per active member account, with a switch in each cell (named "‹right› for ‹person›"); an admin flips one to give or take it at once, and each change goes in the Activity log. More members than fit scroll the grid sideways. Admin accounts hold every right and have no column. An admin can also put anyone's title in any series and make a series private or shared with other people's titles in it, which a member can't (a member's private series takes only their own titles); away from the PC that covers series made at the PC (their Library sharing button shows for an admin there too), and another member's private items still change only at the PC. Settings > My account and look > **Sharing** lists every title and series for an admin, away from the PC too, grouped into Shared and Private, with an **Owner** picker on each row once someone besides the PC owner has been added: give the item to another active account, or to "PC owner"; away from the PC it works on your own items and the ones made at the PC. A title in someone else's private series can't be given to another person ("Move it out of the private series first."), and if the owner changed at the same moment, the picker says "Someone changed the owner just now. Reload and try again." Items made at the PC or with sign-in off belong to the PC owner and start private. Each member row also shows what that person's paid-engine requests cost this month, and a **Paid limit a month (USD)** field (empty means no limit): once their spending reaches the limit, paid engines are off for them until next month (they see a note saying so, and a paid job of theirs that crosses the limit stops; a translation's budget is never more than what is left of their limit, and a queued step on an Ollama cloud model counts as paid, unless the person who added it saved their own Ollama key, and is held to a series auto-run's spending ceiling), including the hosted Ollama model a member's runs use when their settings are chosen for them; the note and refusals say "You've reached your monthly spending limit, so AI runs are paused for you". The monthly cap in Settings still applies to everyone. Every paid request is recorded against the person it ran for. When an action fails, the message now shows the server's own reason under it instead of only "Nothing was changed unless stated otherwise". Each right shows a plain name, and its **i** says what it allows. Too many sign-in attempts in 10 minutes show a short "Sign-in paused" page with a link back to Baihe. A member's Translate with the picker left on Default works when the title's own engine is Ollama (billed, but open to every account). Restoring a backup marks the backup job it was made during as interrupted, not cancelled. Each upload an admin makes from away, and each time the PC turns the away-upload switch on or off, is a row in the Activity log. A backup restore keeps this library's Jellyfin settings, Tesseract, novel-downloader, Whisper model and cookies-file paths, the comic save folder, the web-search server, the upload size limit and the away-upload switch instead of taking them from the backup. A device that is signed out or deactivated no longer shows the page it had open: the sign-in card covers it. Signed in as an admin from away (the household address included), People's buttons and Rights work on member accounts; admin accounts, Settings, Diagnostics and Library tools stay at the PC. With sign-in on, the account button at the top right says your name where the top bar shows its words, when the name is 24 letters wide or less (a kanji, kana, Hangul letter or emoji counts as two, so 12 of them fit; longer names say Account); its panel shows the whole name, your email and Sign out. In People and access > People each person's row says when they were last seen, and **Show devices** lists the devices they are signed in on (label, last use, network), each with its own **Sign out…**; an admin's devices can be signed out only at the PC. Each member row also has **Jobs a day** (no limit unless you set one; empty removes it): once they have started that many background jobs today, new ones are refused until tomorrow, jobs already running finish, and the row shows how many they started today. A job that could not start, or that is cancelled or cleared while it still waits for the GPU, does not count. It sits beside their monthly limit for paid engines; admins have neither.
- **Background services.** `python -m api` also starts the scheduled chapter check and other schedulers (`api/background.py`), and the browser-extension bridge (`services/page_server.py`) when the extension setting is on.
- **Three content modes**: audio drama (your audio or video plus a transcript, aligned to real timing), novel narration (paste the text; the app chunks it, tags speakers with the LLM (splitting again after adding chapters keeps the English, checked marks and notes of every line whose text did not change), translates, and can generate a narration/dub; **Listen** has a **Voice engine** picker and shows each speaker's voice with a **Change voice** link to Review's voices tools) and streamer VOD (see [Streamer VODs and series](user-guide-subtitles.md#streamer-vods-and-series)).
- **Video input**: upload `.mp4`/`.mov`/`.mkv`/`.webm` or download from a URL via yt-dlp (a download in another container, such as `.ogv`, is copied into `.mkv` without re-encoding; a stream yt-dlp's own downloader can't join, such as a Twitch highlight, is fetched again with ffmpeg, which can't use a saved cookie login); the audio is extracted for alignment and the video kept for export.
- **Several downloads from links**: up to 3 run at once, each starting at least 20 seconds after the last. Press Download on more titles and they wait in line ("Queued: 2nd in line" on that title and in Jobs); Cancel works while waiting. You can leave the page. If Baihe restarts, waiting downloads are gone and the Jobs page shows them as interrupted.
- **Why a link was refused**: the message says which rule applied: still live, an upcoming stream or premiere, a playlist or channel, or "This video is 7 h 42 m; the limit is 6 h".
- **Longer than 6 hours**: **Download anyway** raises the limit to 12 hours for that one download. The message shows the disk space it needs, and the free space is checked before it starts. It is not a setting.
- **Video quality**: when you download a video from a link, pick the largest picture to keep: Best available, 4K, 1440p, 1080p (the default), 720p, 480p or 360p. A lower quality takes less disk space and downloads faster; keep 1080p or higher for titles whose subtitles are read off the picture. If the site has nothing that small, the smallest it has is used. The choice is remembered per title. It is not shown for Audio only or a direct file link.
- **Site captions**: a download from a video site (YouTube, Bilibili and others yt-dlp supports) also saves the site's own captions in your title's language when it has any (the person-made track first, else the site's machine-made one). They are hints: Whisper's name prompt starts with the first words of them, and the episode brief the translator reads is told to spell names the way they do. They never replace the lines on their own. **Use the site's captions** (off by default, for each download) makes them the lines of a title with none, with the site's timing and no recognition; machine captions are rough, so check them. A title that already has lines keeps them. Not available with a part or Download again, and a direct file link has no captions.
- **Downloading the same link again** (to get another quality, say): with **Replace the current audio** ticked, the files the earlier download of that same link left are deleted, not kept, because they can be downloaded again. Baihe records which files it downloaded from which link, and deletes only those: a file you uploaded since, a file from another link, an earlier download of only a part, a downloaded file that has been changed since, and anything in a title with Keep original files on are still kept in the title's folder as before. To keep the title's transcription and translation, tick **Download the same video again (keeps the lines)** instead: only the audio and video are replaced and the lines stay as they are. Leave the link empty to use the title's own link; a part can't be chosen. Baihe compares the new file's length with the current one first, and if they clearly differ ("This looks like a different video (25:00 vs 23:40)…") the new file is not used and nothing changes.
- **Only this part**: fill **From** and **To** (h:mm:ss) to download just that section. The default is a fast copy that starts at the nearest keyframe; **Exact cuts** re-encodes the part so it starts exactly where you chose, which takes about as long as the part itself. Subtitle times for a part start at 0:00 for the clip, so add the offset yourself if you need the original times. Not for direct file links, and not while cookie login is on in Settings (the part is fetched by ffmpeg, which would see the cookies on its command line).
- **Why a download failed**: a private video names itself as private (not as a sign-in prompt), and so do age-restricted and members-only videos. A direct file link names a missing file (404), a refusal or rate limit, and a link that opens a web page instead of a file (a share page). A missing ffmpeg is named, for a link and for an uploaded video.
- **"Your network or a DNS filter (for example Pi-hole) is blocking YouTube's video servers"**: the download could not look up `googlevideo.com`. Allow that domain in your DNS filter or network and try again.
- **Phones and large text.** Pages fit a 320 px wide screen and a phone with its text size turned up without scrolling sideways; a stage tab name too long for its tab ends in "…". With a phone held sideways the title and stage tabs scroll away with the page instead of staying pinned. The Reader and Comic name the title as the page heading, so the browser tab shows it.
- **Home screen and Share (Android Chrome).** Open Baihe at your household address and choose Install app or Add to Home screen from the browser menu (Chrome no longer pops up an install offer on its own); it then opens full screen. In the installed app, Share on a page or video in Chrome (or any app) offers Baihe, which asks what to do with the link: **Subtitle this video** (opens Add with the link in place), **Start Live on it**, **Quick read this page** (phone app only, opens it in Baihe Grab) or **Find it in Sources**. The first two need the Import from a link right and are left out for a member without it. Nothing is fetched until you choose, the shared link is never imported by itself and no file is uploaded. Sign in first if the app asks; the shared link is not kept through sign-in.
- **Phone alerts (Android app).** The phone app shows finished titles, failed jobs, runs that wait for you, new chapters and followed channels that went live as phone notifications while the app is closed; a tap opens the exact page (a finished title opens Watch, or the title for a novel or comic). It asks the PC about every 15 minutes, and every 3 minutes for two hours after you leave the app; Android 13 and later asks once to allow notifications. Settings > My account and look > Phone app > **Alerts on this phone** turns it off. In the alerts bell, a finished job now has an **Open** link to the same page.
- **Copied links (Android app).** Copy a video link (YouTube, Bilibili, Twitch and similar) or a link to a comic or novel on a site Baihe supports, then open Baihe: it asks **Subtitle this?** (opens the share choices) or **Read this?** (Quick read) once for that link. Settings > My account and look > Phone app > **Offer to subtitle or read a copied link** turns it off. Android may show its own "pasted from your clipboard" note the first time Baihe looks at a new copy.
- **Live in a floating window (Android app).** While a Live picture is playing, going Home (or pressing **Float the picture** under Viewing options) keeps it in a small window over other apps, with the captions drawn on it; tap the window to come back. It needs Captions over video on to show the lines. Settings > My account and look > Phone app > **Float Live in a small window when I leave the app** turns it off. If Android's own picture-in-picture switch for Baihe Studio is off, nothing floats.
- **Phone app updates (Android app).** The PC now looks for a newly published phone-app build by itself (about every 10 minutes, when a phone asks), so the **Update Available** prompt no longer waits for someone to fetch it on the PC first. Settings > My account and look > Phone app > **Check for updates** asks right now and tells you whether you are up to date, can't reach Baihe, or have an update to install. The phone app no longer installs updates quietly when you leave it: it always shows **Update Available** and waits for your tap, because the quiet install could fail with no sign.
- **Slow or unreachable Baihe (Android app).** When Baihe is slow to answer on first open, the app shows **Connecting to Baihe…** and retries by itself for about 30 seconds instead of Android's raw error page; only if it still can't connect does it say so and show **Retry**. Every native screen of the app (the Studio | Grab bar, Grab, Grab settings, history and bookmarks, the novel reader, and the app's dialogs) follows the look Baihe is showing: light, dark, Sepia or OLED (a newer app build is needed).
- **Screen readers.** Each page's headings go one level at a time (page title, then its sections, then their parts), so jumping by heading level never skips a level.
- **Line tools.** A line's actions sheet in Review has "Alternatives (AI)" and "Grammar breakdown (AI)" for study. When one of these, or another one-line AI action (Improve, Explain, a line retry, the episode summary, Learn style, the Reader's questions), fails, the message says why when it can: the key was refused, a rate or daily limit was reached, the engine was too slow or could not be reached.

## Running the app

Double-click `start.bat`, or from the repo root inside the venv (once `frontend/dist` exists):
```bash
python -m api     # then open http://127.0.0.1:8600/
```
Set `BAIHE_API_SERVE_FRONTEND=0` to run API-only.
