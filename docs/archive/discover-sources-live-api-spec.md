## 3. Security model

**ToS/robots reality (verified).** `ladder.check_terms` is a `pass`, deactivated 2026-09-27 by explicit user decision (Step 90); its tests are skipped (`tests/test_sources_workflows.py`). There is no robots.txt fetcher or parser, only static `host_min_interval` crawl-delays. Recorded terms data still exists: `site_terms.SITE_TERMS` (9 sites) and each adapter's capability `terms` block. API rule: every fetch service calls `ladder.check_terms(...)` at the service boundary (no router-only gate), so re-enabling that one function covers the API. Show recorded findings as informational and never label anything "permitted" (UNKNOWN is not PERMITTED, `site_terms.py:12-14`). Needs the user's answer (Q1).

**Sign-in and cookies.** Session state never crosses the API. The profile is `<library>/profiles/<key>/` (`store.browser_profile_dir`) and `auth_browser` never reads cookies (`auth_browser.py:21-24`). The API returns only `has_saved_signin` bools and the `LoginCheck` message and facts; free text (`lines`, `detail`) must be scrubbed of paths (`ladder._browser_outcome` redacts secrets only; Playwright launch errors contain the profile path, HYP). `open` and `forget` are local-only (S-6). Implicit hazard: `generic_import.fetch_page` switches to the signed-in tier automatically when a profile exists (`generic_import.fetch_page`, by default), so any remote-triggered URL preview or import for a signed-in domain would read pages as the owner's account. Give services an explicit `allow_signed_in` argument that the router sets false for non-local requests, or decide otherwise (Q2); `generic_import.fetch_page` now takes `allow_signed_in` and `allow_browser`, and the Sources services pass them as `local`. `cookies_browser` (yt-dlp reading the PC's browser cookies) and `cookies_file` (a server path) were only in Streamlit session state; the API accepts neither as request parameters, for downloads (`front_door.import_video`, `video_download.cookie_options`) or live capture. A saved Settings cookie setting now exists (`settings_service.get_cookie_settings`) and is used only for requests made at the PC (`live_service.start_session` with `use_saved_cookies`, `url_media_service`).

**SSRF.** Reuse the `metadata_service` pattern (IP validation on every hop, pin to the validated IP, keep SNI and cert checks, `timeout=`, capped bytes, fixed error text) through D-0. Known holes if a raw user URL reaches them:
- `page_fetch.fetch_static` is guarded: it follows redirects by hand, validates every hop with `url_guard.resolve_public` and connects through `metadata_service.pinned_get` (`page_fetch.py:376-398`); used by `navigator` and `smart_fetch`.
- `sources.http._requests_transport` is guarded: it follows redirects by hand (`allow_redirects=False`, at most `MAX_REDIRECTS` = 5), validates every hop, the first included, with `lib.url_guard.resolve_public`, and without a proxy pins the connection to the validated address (`http.py:543`).
- `page_fetch._rendered_page` and `fetch_with_profile` are guarded: every Chromium they launch sends all its traffic (navigations, redirect hops, subresources, fetch/XHR, WebSockets) through a local `_PinningProxy` that checks each target host with `url_guard.resolve_public` and connects to the validated IP itself, and every context also installs `make_request_guard()` (`page_fetch.py:85-100`). Chromium never resolves a name, so there is no DNS-rebinding window.
- **Blind SSRF through adapter URL matching (confirmed when written, since fixed):** adapter URL patterns were unanchored `re.search` (`bilibili\.com/video/...` and `b23\.tv/`; `front_door._VIDEO_URL`), so `http://169.254.169.254/?b23.tv/` matched, `normalize_url` then did `"b23.tv" in url` and called `client.request("HEAD", url)` with redirects, and the same URL went to yt-dlp. Now `base.host_url_search` (used by `SourceAdapter.matches_url`, `BilibiliSource.normalize_url` and `front_door`) requires the parsed host to match, a resolved short link must lead to a Bilibili video or bangumi page before it reaches yt-dlp, and the HEAD goes through the validating `SourceClient` transport.
- `live_translate.resolve_stream_url` and ffmpeg (`start_segment_capture`) fetch client-supplied URLs with their own DNS. The API's `live_service` validates both the client URL and the resolved stream URL with `url_guard.resolve_public` first, so only the DNS TOCTOU remains.
Rules: user-supplied URLs go through D-0 for the fetch and use no rendered or auth tier for non-local requests; adapter routing requires the URL host to match the adapter's known hosts, not a substring; API inputs to adapters are ids, never URLs; video and Live URLs get scheme and public-host validation plus an allowlist of platform domains; a yt-dlp and ffmpeg TOCTOU remains (accept it or restrict to local, Q3). `metadata_service.pinned_get` sets `trust_env=False`, ignoring `http_proxy_url` and environment proxies (HYP: in a proxy-only network D-0 fetches fail).

**Rate limits and concurrency.** Per-source pacing and a semaphore live in-process (`_source_state` in `sources/http.py`); an API process and any second process (the Streamlit app, since deleted, was the other) each pace separately, so running both doubles the request rate to a source. A sync endpoint blocked in `_wait_turn` ties up a threadpool worker, hence jobs for anything paced. Add a per-client cap: at most one running Sources or Discover network job per kind (fixed ids), 429 `rate_limited` for a burst of job starts, and caps on URL counts, chapter counts and page size. A remote device may: read catalog and status, search (paced on the host IP), preview. It may not, until D5/D6 exist: sign in or forget sign-in, change proxy or pacing floors, use signed-in reads, use paid engines without a permission, or set cookies.

## 4. Live capture (separate proposal)

- **L-1, polling only (thin; unblocked once policy is set).** `POST /api/live/sessions {url, source_language, whisper_size, segment_seconds, overlap_seconds, engine, max_minutes}` returns `{session_id}`: checks the platform allowlist and public host, resolves the key server-side, starts a job under a per-session id (not `live_capture`) with `gpu_touching=True`, and hard-stops after `max_minutes` (`process_chunk` calls the engine unbounded; `run_live_job` takes `max_seconds`, which `live_service` sets from `max_minutes`; no spend-cap check found, HYP). `POST /api/live/sessions/{id}/stop` does `live_translate.bump_generation` then `request_cancel`, or `cancel_queued` if queued (bump first, `live_tab.py:110-127`). `GET /api/live/sessions/{id}?after=N` returns status, message and `cues[N:]`, never a traceback (the job dict holds one; `JobRecord` does not). Use a per-session `tempfile.mkdtemp` directory removed on finish: the Streamlit tab uses a fixed `tempfile.gettempdir()/baihe_live_capture` (`live_tab.py:95`) and `run_live_job` did not clear it at start, so stale `chunk_*.wav` files from an earlier run were processed as new (HYP from reading); `live_translate.start_segment_capture` now calls `clear_stale_chunks` first, and a per-session directory also avoids two sessions colliding. Built in `services/live_service.py` and `api/routers/live_routes.py`.
- **L-2, optional SSE.** `GET /api/live/sessions/{id}/events`, an async generator over an in-memory poll of `background_jobs.get_status(id)["result"]`. `event: cue` with `id: <index>` for `cues[last:]`; support `Last-Event-ID` (the list only grows; a new session has a new id); `:` heartbeat every 15s; `event: end` on terminal status; cap concurrent streams (about 4); `X-Accel-Buffering: no` and `Cache-Control: no-cache`. Fit with `background_jobs`: read-only over in-memory state, no persistence, lost on restart; `job_records` carries no result so a session started in another process is invisible. Same-origin GET works with the current CORS (`allow_methods=["GET"]`, the CORS middleware in `api/server.py`). Unknown: whether the Vite dev proxy and any remote-access proxy pass streaming unbuffered; verify by hand. If they buffer, L-1 polling is the fallback (what `useJob` does). Not built as a per-session route: live status is the `live` topic of the generic `GET /api/events` stream (`api/routers/events_routes.py`), and the client fetches new cues with `GET /api/live/sessions/{id}?after=N`.

## 5. Rules from CLAUDE.md that apply, with specific risks

- **No AI results by position:** `bulk_import.extract_listing_entries_llm` and `adaptive` map picks to block, link or image ids (ok); `live_translate.process_chunk` translates one text at a time (ok); `dedupe_content` is positional and not touched.
- **No key in a URL, log or error:** `ladder._browser_outcome` redacts only secrets, not paths; `pipeline.run_import_job` stores `f"{reason}: {e}"`; `LiveCaptureError` text embeds the yt-dlp exception (`live_translate.resolve_stream_url`); the `access_attempts.url` column stored pasted URLs with their query strings (`store.log_attempt` now stores scheme+host+path only); `suggestion["source_url"] = url` (`metadata_service.autofill_suggestion`) echoes user input. Every response text goes through `redact_secrets` plus path and query stripping.
- **Every HTTP call has `timeout=`:** `tests/test_static_analysis.py` scans `services/` and `api/` with `session_verbs=True`, so `session.<verb>` and names assigned from `requests.Session()` are checked too (the checker was extended as proposed; `pinned_get`'s `session.get` passes `timeout`). yt-dlp calls (`live_translate.resolve_stream_url`, `BilibiliSource._extract`) set no explicit `socket_timeout` (HYP: its default applies).
