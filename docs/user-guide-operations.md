# User guide: running and fixing it

Part of the [user guide](user-guide.md).

## Quick video translate

On Make subtitles, "From a link" takes a video link and one button, One-Click Translate, makes a new title and runs Download, Transcribe, Translate and Export subtitles for it through the Queue, with the profile chosen in Settings > Quick video translate, shown on the card as "Profile: <name>" (the button stays off until one is chosen). A profile is a saved translation profile; its Quick video translate section sets the source language the title is made in, the export format and language, and the language packs. It works at the PC only, like any link download. Progress shows under the button and in the Queue; if a step fails the later steps are skipped and the reason is shown. A request that is refused (no profile, no source language in it, a paid engine your account can't use, a link that isn't public) makes no title.

"Watch once" marks the title as temporary. When the run is done, Open shows it in Review with the video, and "Done watching, delete" removes that title with its files. Only a title made that way can be removed there, and one nobody removed goes after 48 hours, when the app starts.

## The job queue

The Jobs page has a Queue card (below the job list, or above the empty state when nothing has run yet) for lining up work and letting it run hands-off, for example overnight. Pick a title and a step (Transcribe, Translate or Export subtitles) and add it; reorder with Move up and Move down, remove an item, or press Retry on one that failed, was skipped or was interrupted. Click the Queue heading to fold the card down to its status line; it remembers this in the browser and stays open while the queue is running.

- Items run one at a time, in order, through the same path as the stage's Run button, with the title's saved options. Transcribe replaces the title's lines (the old ones stay in line History); a title that transcribes from a pasted transcript can't be queued. Export subtitles saves English SRT as the title's subtitle download. Open "Saved settings for this step" to change a step's settings (Transcribe, Translate or Export) for that queued item only; the title keeps its own.
- **Translate items spend money.** On a paid engine a Translate item uses your API key and costs money; the card says which engine before you add it. The queue respects the Spending caps in Settings: before each Translate item it checks this month's cap and skips the item ("Skipped: ...") when the cap is used up or the estimate is above what is left, and the run itself still stops at the cap. With no monthly cap set, paid Translate items are skipped: unattended paid work always has a ceiling.
- "Start queue now" runs it; "Start at" runs it once at that time on the PC's clock, then the schedule clears. Pause starts no new item; the running one finishes, or cancel its job in the jobs list. "Stop the queue when an item fails" is off by default, so a failed item is marked and the next one starts.
- If the queue can't be read, the Jobs page shows the error in the card's place; it goes away by itself once the queue answers again.
- An item that can't start (the spending cap, a job already running on that title, a deleted title, a missing key) is marked "Skipped" with the reason, and the queue moves on.
- After a restart nothing runs on its own: an item that was running shows "Interrupted", and a start time that passed while Baihe was off shows "Missed: start now?" until you start or dismiss it.
- With sign-in on, each account sees and changes only the items for its own titles (at most 50 items per account); only the PC owner starts, pauses or schedules the queue. A queue restored from a backup is stopped, like after a restart.

## Reliability

- One failure breaks only that thing: each React page has an error boundary, database connections are reclaimed after errors, destructive writes (`save_lines`, `save_bubbles`, history snapshots) run in transactions with rollback, and optional packages are imported lazily so a missing one disables only its feature.
- Batch work isolates failures: one failed TTS line leaves only that line silent; one failed page doesn't stop a bulk scanlate job; diarization failure keeps the alignment already saved.
- API calls back off exponentially on rate limits (up to 5 attempts) and fail fast on real errors.
- A disk or file problem names its cause instead of "The action failed": a full disk, a read-only library folder, a damaged or busy library database, a file Baihe's account may not open ("Permission denied", for example when the boot service's account cannot read the library folder; the app log names the file), and a file another program holds open. Removing a title's raw novel text tells these apart too: a file Baihe may not change says "Permission denied", not that it is in use.
- Translation saves after every batch and skips already-translated lines on re-run; use "force re-translate everything" for a full redo.
- Settings holds each API key once; keys are never shown back by the API. When Settings can't load (Baihe stopped, say), it says so in one banner with Retry, which reloads the settings and their list together. Settings has six tabs (Translation and keys, Costs, Notifications and backups, Account and display, Integrations, Performance and advanced) and a search box that opens the tab and card it finds. Every card folds; the app remembers which are open, and one button, "Expand all" or "Collapse all", acts on the tab you are on. The first time you open a tab only its first card is open; after that the app keeps the cards as you left them, and a closed card shows its current value in one line. Someone without the settings permission (or an admin on the household address) sees only the Account and display cards, with no tab bar or search, and away from the PC the cards that only work on the PC are left out. A signed-in member can save their own Ollama key under Account and display > "Your Ollama key", so their Ollama cloud runs use their own account; it is never shown back. An admin's cloud runs always use the PC's own sign-in, so a key saved before the account was made an admin is ignored until it is a member again. The public address check and the sign-in accounts are on the People and access page, and ports are on Diagnostics > System.
- Settings cards by tab. **Translation and keys:** Which engine does what (with no key saved yet, its Engines and keys list comes first and each missing key is noted once), Translation style, Language packs. **Costs:** Spending (monthly cap), Past costs, Spend history. **Notifications and backups:** Notifications, Automatic backups, Save folder, App updates. **Account and display:** Sharing, Update Baihe (an admin on a copy started with start.bat: Check for updates, then Update and restart; works from a phone too, and says why when it can't; if start.bat can't start Baihe again, start it by hand and the card names `restart_after_update.log` in the Baihe folder), Display, Menu items, Signed-in devices, Extension tokens per computer, Your Ollama key. **Integrations:** Jellyfin, Web search, Browser extension. **Performance and advanced:** Jobs and GPU (GPU use, a limit on GPU jobs at once, Keep free memory, Resume interrupted batches), Offline, paths and limits (Ollama URL, where "localhost:11434" or "http://localhost:11434/api" is saved as "http://localhost:11434", and context window, offline Whisper model folder, OCR backend, Downloads, Program locations, Upload size limit), Timing and splitting, Advanced transcription, Developer Mode.
- SQLite runs in WAL mode; the review table is paginated; real token usage is logged per drama (estimates only, since prices change).
- GPU acceleration is optional (Whisper, diarization, local cloning) and falls back to CPU if CUDA isn't available. Whisper picks the fastest number format the card supports, so older cards without float16 (GTX 10xx) still transcribe on the GPU.
- The novel reference is sent as a prompt-cached block per drama. A very long novel (200k+ Chinese characters) may not fit; trim to the relevant arc or compress it into a glossary.
- For 50-100+ dramas: filter the Library by status and line the work up in the Queue card on the Jobs page.

## Troubleshooting

### If Hugging Face is unreachable

If Whisper's first download fails with `getaddrinfo failed` or `LocalEntryNotFoundError`, it is a network problem. Likely causes on Windows, in order:
1. Antivirus or firewall blocking `python.exe`: allow it.
2. A VPN that is connected but not routing.
3. DNS: `ipconfig /flushdns`, then try `1.1.1.1` and `8.8.8.8`.
4. A DNS blocker (Pi-hole, AdGuard, corporate filter) answering `0.0.0.0`. Check with `nslookup huggingface.co`; if it answers `0.0.0.0` or `::`, allow `huggingface.co`, `cdn-lfs.huggingface.co`, `cdn-lfs-us-1.hf.co` and `hf.co` (the `cdn-lfs` hosts serve the model files), then flush DNS. The app names this case itself.
5. Blocked by your ISP or region: set a mirror, e.g. `$env:HF_ENDPOINT="https://hf-mirror.com"` (PowerShell) before `python -m api`.

Fully offline: download a `faster-whisper` model elsewhere and point Settings > System > "Offline, paths and limits" > "Offline models" > "Offline Whisper model folder" at it.

### GPU transcription failures ("cublas64_12.dll is not found")

The app already retries on CPU, and says so in the run summary ("ran on the CPU because the GPU couldn't be used"). The cause is that Whisper's engine (CTranslate2) looks for the CUDA 12 libraries (cuBLAS and cuDNN 9) on the Windows search path, and they are not on it. The GPU PyTorch install carries those libraries in its own folder, so Baihe now finds them there by itself when it starts and before each Whisper run; you do nothing. If you still see the message, open Diagnostics > Packages and installs: when the libraries are found nowhere, a "CUDA runtime for GPU Whisper" row (Recommended) appears with an "Install…" button (PC only). It installs NVIDIA's cuBLAS 12 and cuDNN 9 packages (about 1.2 GB) and needs no restart. The Transcribe tab's line reads "GPU unavailable: ..." while they are missing. Turn "Use the GPU for transcription" off (Settings > System > Jobs and GPU) to silence it. Background: `docs/technical-notes.md`.

### Sharing the PC with other programs (Keep free memory)

If this PC also runs something else that needs the GPU or RAM (a media server doing hardware transcoding, say), set Settings > System > Jobs and GPU > "Keep free memory" > "Keep free graphics memory" and "Keep free RAM". Before a local model loads (Whisper, Qwen3-ASR, the aligner, vocal separation, a local Ollama translation model, the dub voices), Baihe compares the model's estimated size and the memory that is free right now with that reserve. If loading would break it, the job stops at once with a message saying what is needed, what is free and what is kept free, instead of running out of memory halfway. Then unload another model (Diagnostics > Models > Models in memory, once no job is running), pick a smaller model or int8, or lower the setting. The default is 0 (off). Sizes are estimates, so leave a little slack. Cloud engines and an Ollama on another machine use none of this PC's memory and are not checked. If the memory can't be read (no NVIDIA GPU, or an OS Baihe can't query for RAM), the check is skipped and Models in memory says so. A refused Ollama translation stops the run after the first batch rather than retrying every batch. A Whisper model folder is sized by its folder name when it is a known model; otherwise no estimate is made and the check is skipped. Not yet covered: diarization, OCR other than the manga model, and a llama.cpp server.

### GPU PyTorch (NVIDIA)

`pip install torch` gives a CPU-only build on Windows, and installing torch, torchvision and torchaudio separately can leave mismatched versions. Diagnostics > Packages and installs > GPU PyTorch shows your GPU, driver and installed torch family, and "Set up GPU PyTorch…" (PC only) installs the matched CUDA build the app is tested with, then checks that CUDA works. The driver line compares your NVIDIA driver with what the installed CUDA build needs (the recommended build when none is installed): for a card older than compute 7.5 such as a V100 (the CUDA 12.6 build), any driver from 528.33 (Windows) or 525.60.13 (Linux) is fine and no newer one is suggested; otherwise CUDA 12.8 recommends 570.65 or newer, and 528.33 still works. Afterwards every Install/Update pins the installed torch family, so a package wanting a different torch is refused instead of replacing your CUDA build. On an NVIDIA PC without PyTorch, a package that needs it (demucs, pyannote and the like) is refused until GPU PyTorch is set up, so it can't bring in the CPU build. The set-up itself is refused when it would take a package Baihe needs below the version the app asks for. Every refusal names the packages and versions involved.

### The Export stage

Export is a list of collapsible blocks, one per thing you can make: Video with a subtitle track (SRT, or ASS to keep overlapping lines and speaker colours; ASS is always saved as MKV and plays in VLC and mpv, while some TVs and phone players ignore the styling), Burned-in video, Video with the dub audio, Audiobook, EPUB and Subtitle file (SRT, VTT, LRC or ASS). The first block is the one that fits the title's kind (a video leads with the video blocks, a novel with EPUB, an audio drama with Audiobook, an imported subtitle with Subtitle file; a comic's Export stage points to Scanlate instead) and starts open; the other blocks follow and start folded. Every kind still lists every block. Which blocks you keep open is remembered per kind of title. A block that cannot run yet says why in one line (no source video, ffmpeg not installed, no dub or narration yet). Send to Jellyfin with the ASS format uses the same ASS style set in Subtitle file. Its errors name the cause: an address that redirects, an address that answers but isn't Jellyfin, a Jellyfin server error, a library folder the app can't write to or a full drive. "Next to a Jellyfin video" lists the videos in your library folder first, skips disc folders (a DVD or Blu-ray folder has no single file to put a subtitle beside), and counts a subtitle tagged "zh-CN" as Chinese. ASS, burned-in and ASS soft-sub exports refuse a title with no text in the chosen field, as SRT does. A backslash in a line is shown once in ASS and burned-in video. A long Chinese, Japanese or Korean line is broken onto several rows in ASS and burned-in video (at most 15 characters a row at the Clean size on a landscape video, fewer at bigger sizes, with a thicker outline or on a portrait phone video), because players break rows only at spaces and it ran off both sides of the picture; a narrower wrap width set in Advanced still wins. A downloaded ASS file and the ASS sent to Jellyfin are sized for the title's own video (or the Jellyfin video it goes next to); with no video they assume a landscape one. A portrait phone video gets 6 characters a row at the Clean size, which fits even in the widest Chinese and Japanese fonts. In LRC, a line followed by an untranslated one disappears at its own end instead of staying up until the next translated line. Importing an ASS file keeps braces written as `\{` and `\}` as text, as players show them. A soft-sub track of the original text is tagged with the title's language (Japanese, Korean or Chinese), and a video with no audio track can get one. Subtitle files list cues in time order, also after a line was retimed before the one above it, and so does the Export all zip. A downloaded SRT with Chinese, Japanese, Korean or any other non-English letters starts with a UTF-8 marker (BOM), so TVs that otherwise guess the wrong encoding show the text correctly; an all-English SRT is saved as before. An EPUB only embeds images from the title's own images folder.

### Tidy cue timing, and the reading-speed check

The reading-speed check only raises a flag; it never changes a saved time. It judges the English subtitle, at the Netflix Timed Text Style Guide's 17 characters per second (Relaxed allows 20, and streamer titles allow 20% more than Relaxed). Cues under 1.5 seconds are never flagged. A flag is often right that the person really talks that fast, so its note says what is true: either the next line leaves room and the cue "could be shown N s longer", or "The speech is this fast: shorten the text". Nothing stretches a cue to fit. Reading-speed flags you dismiss are not remembered: flagging again, or finishing a translation, flags the line again if it is still too dense.

**Tidy cue timing for players** (Export > Subtitle file > Advanced, SRT and bilingual SRT only, off by default and remembered with your other export choices) makes the exported file friendlier to players without touching your saved times. It lengthens a cue shorter than about 0.83 s into the silence after it (never past the next cue, never by more than 1 s) and leaves 2 frames between cues that touch by shortening the earlier one by at most 2 frames. Cues over 7 s are not cut: they are listed after the export for you to review. The frame rate is read from the title's own video (ffprobe, five-second limit); with no stored video, or if the probe fails, 24 is used. ASS and VTT keep the times as saved, so overlapping cues stay fully visible there (in the burned-in video too); SRT, bilingual SRT and LRC shorten the earlier cue to the next one's start. The download's `X-Cues-Extended`, `X-Cues-Trimmed` and `X-Cues-Left-Long` headers carry the same counts.

### If your exported subtitles are blank

A `.srt` with correct timestamps but no text means the lines aren't translated yet (an aligned but untranslated drama exports every entry empty). Check that the lines are translated (the Library header shows "X of Y lines" for the whole library; Review shows each line) and press Translate first (Ollama is free). The export buttons warn before this: zero translated lines disables the English/bilingual downloads, and a partial translation shows how many lines will export blank.

## Testing & diagnostics

### Testing

The test suite is fully mocked (no GPU, models, API keys or network) and uses an isolated temp database, so it never touches your library.

```bash
pip install -r requirements-core.txt pytest -c constraints.txt
python run_tests.py              # everything (a wrapper around pytest)
python run_tests.py -k history   # a subset
```

Frontend checks, from `frontend/` after `npm ci`: `npm run lint`, `npm test` (vitest), `npm run build` (typecheck + bundle) and `npm run e2e` (Playwright against a seeded throwaway library; uses ports 8611 and 4174; point `PLAYWRIGHT_CHROMIUM_PATH` at an installed Chromium, or on your own PC install one with `npx playwright install chromium`). The repo's `CLAUDE.md` has the maintainers' fuller command list.

### Diagnostics ("Check my setup")

The Diagnostics page (nav item "Diagnostics") has four tabs, the same kind of tab row as Settings. The tab you last used is remembered, and links from other pages (for example "Open Diagnostics" on a job, or on Before you run) open the right tab and card. A tab with a number on it has something that needs a look (a setup problem, an install waiting for the next start, a model that is retired or older). The first time you open a tab only its first card is open and the rest show a one-line summary. Each card can be folded, and the app remembers which.
- **Setup** -- **Recommended installs** (the GPU, FFmpeg and JavaScript runtime found, then each optional piece with Ready or Missing, why you would want it, its size and how to install it; **Install all** sets up GPU PyTorch first, then every other missing package; **Update these**, at the top of Packages > Install by task, updates every installed package older than the app needs in one go, and refreshes Playwright's browser if you use one) and the **Setup** card: Python version, whether ffmpeg is on PATH, the JavaScript runtime, GPU and PyTorch state (Unknown, not OK, for a GPU the app has not been able to check because PyTorch is not installed), the app files and whether the library folder is writable, problems first.
- **Packages and installs** -- every install lives here. If Baihe runs as a Windows service, turn off both services ("Baihe Studio" and "Baihe Studio remote access (Caddy)") and start Baihe from the Start menu first; installs are refused while they are on, and the page says so. **Packages** has installed versions, install-by-task presets, per-package Install / Update (PC only) with "Check for package updates", a "Test first" upgrade check and the GPU PyTorch set-up. **Browser support** and **JavaScript runtime** (Deno) cards appear when Setup finds those missing. **Speaker detection** shows whether pyannote and your Hugging Face token are ready, with an on-demand check that the token can open the gated models.
- **Models** -- **Model status** lists every model the app is set up to use, flagged when it is retired, deprecated or no longer listed by its provider (the provider check runs only when you press "Check providers now"; engines that need a key link to Settings). **Models** lists each engine with its version and the model files you have downloaded (size, Delete); an engine that isn't installed says what it is for and links to Packages and installs. **Test my models** runs one transcription, OCR read and Ollama translation with the models you have. **Models in memory** shows what Ollama, the app and the GPU hold right now, with Refresh and a confirmed "Free app models" (PC only, disabled while a GPU job runs). A link to the Benchmark Lab, which is its own page (below), sits at the bottom.
- **System** -- **Ports**, **Log** (recent redacted lines of the app's own log, 50/100/200) and, last and closed, **Reset library** (described in [Resetting for testing](user-guide-setup.md#resetting-for-testing)).

The list of every background job (translate, transcribe, dub, diarize, Live capture, etc.) with progress, cancel and delete is the separate **Jobs** page (a round dot with the running count sits on its menu icon, also when the menu shows icons only). Each finished job says how it ended: a force-stopped job says so, a job still running when Baihe was stopped reads "Interrupted: Baihe was stopped while this was running", a bulk translation that gave up after several failed titles says so, and a cloud batch that stopped checking, hit the spending cap or had failed batches reads as partly done rather than Finished, and a cancelled bulk review pass (flags or consistency) reads "The job was cancelled." rather than calling itself a translation. When a bulk translate from the Library starts nothing, the message names each skipped title with its own reason; accounts and the activity log are on **People and access**.

The redacted support report (strips API keys, paths and user names) is in the header's "Report a problem" dialog ("Copy a report for a bug"). The App Assistant (Developer Mode, PC only) is its own page.

Run Diagnostics first whenever something isn't working.

### Costs

Costs are estimates from the app's price table. Settings > Costs > Spending sets the caps. Settings > Costs > Past costs (closed until you open it; "Check past costs") previews entries that were priced at a higher model's rate; nothing changes until you press Apply, and "Undo re-cost" puts the old figures back. Settings > Costs > Spend history lists spend and calls by month for the last months, with By operation, By engine and model, and By title breakdowns for a chosen month and a Download CSV. Past costs and Spend history are PC only; the Library tools page also lists estimated cost per title.

**Runs stop themselves.** A translate run ends after 3 batches in a row fail or after about 10 minutes of waiting out rate limits (the reason is shown and the lines already translated are kept), Live refuses to start once the monthly cap is spent and ends on the cap or after 3 failed translation requests in a row, and Quick translate has no length limit but stops before the chunk that would pass the monthly cap and returns what it finished, showing the estimated cost and the cap left before you press Translate. Two runs going at once can each read the same month total before either logs its next request, so together they can pass the cap by at most one request each.

**Open a file (Quick translate).** A `.txt` or `.md` file saved as GBK, Big5, Shift-JIS, EUC-KR or UTF-16 is read in that encoding instead of losing its characters.

**Read from a screenshot (Quick translate).** The "Read from a screenshot…" button beside Translate and Clear takes a pasted (Ctrl+V), dropped or chosen PNG, JPEG or WebP picture, lets you drag a box round the text and enlarge it, and sends just that crop to a vision engine (Claude, Gemini, OpenAI or Ollama; DeepSeek takes no pictures). The characters it returns are added to the text box as they are, not translated. It works at the PC only (the button is hidden on other devices, which can still paste typed text). The picture follows the page-upload limits (30 MB, and 25 megapixels here), is written out fresh without its metadata and cut down to 2000 px on its long side before it is sent, and is not kept. A paid engine shows its estimated price (the most a request can cost) and the cap left first, is refused when the cap is spent or the picture would pass it, and is logged like any other paid call. Ollama is free; the model must accept pictures (Gemma 4 should; untested on a real PC when this was written). If the engine fails, the message gives its reason (for example a refused key).

**Read from video (Review).** On a wide screen with a video, the side card has a small picture-icon button; the panel stays closed until you open it (and stays as you left it on that browser). Pressing Ctrl+V with a picture on the clipboard while a line is selected opens it with that picture, so a screenshot needs no saving; other pastes are untouched. Inside, **Use this frame** and **Use frame at line start** take the picture from the player instead. Drag a box round the hard-sub caption (the box stays for the next picture) and **Read into this line** puts the characters into the selected line's Source box as an unsaved edit, so Save, Undo and the conflict check work as for any edit. **Read & translate** does the same and also fills the line's Translation box with the title's own engine's English (an unsaved edit too). With lines ticked in the list, **Read all selected lines** reads each ticked line's frame at its start (same box, enlarge and engine) and saves the characters as that line's Source at once, stopping at the first failure; lines already read stay saved. It uses the same read as above (same permission, price shown first, PC only). If the browser can't take a picture from the video, paste a screenshot instead.

**Every paid loop stops itself too.** The AI flag pass, consistency check, emotion tagging, translation notes, Fix flagged, glossary extraction, narration tagging, re-segmentation, Scanlate, the Benchmark lab and its judge pass end after 3 failed requests in a row, after about 10 minutes of waiting out rate limits, or when this month's cap is spent, and the job's result says why ("Stopped: 3 requests failed in a row", "Stopped: monthly cap reached"); whatever was finished is kept. A cloud batch checker gives up after about 15 minutes of failed status checks or 49 hours of the provider still reporting it pending, with a plain reason (the batch stays recoverable through "Check now"), and a DeepSeek off-peak run goes back to waiting when the half-price window closes. Work that runs with nobody watching (a bulk batch, an off-peak run, a bulk series, Start Live automatically) is refused until a monthly spending cap is set in Settings. Line actions, Reader, Discover, metadata lookup, the Sources AI fallback and Groq transcription now write every paid call to the usage log, failed requests too (Groq at no cost when it failed, and under its own name when the audio length could not be read); the review passes, Fix flagged, glossary, narration, re-segmentation and Scanlate keep logging each successful request through their own callbacks, so a failed request there adds no row. A job a rule stopped shows the reason on the Jobs page, and the batch checker fails a batch as expired only when the provider still reports it pending after 49 hours.

### Benchmark Lab

**Uploads from away.** Uploads are PC only unless Settings > Developer Mode > "Allow uploads from away" is on. Then an admin signed in on another device can upload audio or video (also with Transcribe), import a subtitle file, attach novel text or an EPUB, save the raw novel or the English reference, and add comic pages or a cover, under the Settings upload limit. The switch turns itself off after 7 days, and whenever Developer Mode is off. Link downloads, using Sources chapters as narration text, lightnovel-crawler, chapter OCR and every delete stay at the PC.

The Benchmark Lab page is behind Developer Mode (Settings > Developer Mode), like the Assistant: with the mode off it is left out of the menu and the command palette, and the links to it from Diagnostics (including "Compare in Benchmark Lab") open a notice with a link to Settings. It checks whether a model, engine or setting change actually helps on your own content. No test data ships with the app: you supply it.

- **Golden sets.** Cases are translation pairs (source text plus a reference translation) or audio clips with their reference transcript, in a named set with a tier: public (a set you import, e.g. a FLORES-200 slice), application (your own corrected translations) or regression (a line you fixed by hand and kept). Import pasted JSONL (`{"source": ..., "reference": ...}` per line) or TSV (`source<TAB>reference`), up to 500 cases; add one case by hand; upload your own clips with their transcripts ("Your own clips", up to 250 at once); build a set from a title you have reviewed ("Build a set from a reviewed title"); add a title's corrected lines with their audio ("Add a title's corrections to a test set"); or keep a corrected line from Review with "Add as regression test". "Show cases" lets you read, exclude, fix the reference of or delete a case. Nothing is downloaded; importing, adding and building are PC only.
- **Run.** Pick a stage (translation, transcription or OCR), a set, and one to four engine/model configs; two or more run the same cases side by side (Model Arena). Press "Estimate cost" first: paid engines stop at the monthly cap. Transcription runs use the same per-title settings a real run would; "Translate like a title" runs a title's cases together, in order, with context, and can add a series' translation-memory examples to the prompt or set a temperature (DeepSeek, Gemini and Ollama only). The **Settings sweep** (transcription) and **Translation sweep** cards on the same tab try one setting at a time on your own cases, check the winner on titles the sweep never tuned on, and **Approve** saves it as a setting profile; nothing changes by itself.
- **Scores.** Translation uses chrF via `sacrebleu` when installed, else a text similarity ratio; transcription and OCR use 1 - CER (1 - WER for space-delimited languages), via `jiwer` when installed, else a built-in scorer. For Chinese, both texts are first converted to Simplified (OpenCC, else a built-in character table), so Traditional against Simplified is not an error; the run records which converter it used, and the Traditional/Simplified counts still show the script. Japanese and Korean are not converted, and Chinese scores from before this change were script-sensitive. Each result records its metric and scorer.
- **Results.** Every run is saved (engine, model, score, latency, cost, peak VRAM, per-case pass/fail) under "Recent runs"; tick runs and press "Compare in Arena" (export a run or comparison as CSV or JSON; delete a run on the PC). Transcription runs on timed clips also report line timing (start and end error, merged, split and missed lines). A scheduled re-evaluation of candidate models against your production model is on the same page. The Arena refuses runs whose cases were scored by different metrics (for example before and after installing `sacrebleu`), and a run that stops on an error keeps that error as its note. An Ollama translation sweep tries only models pulled on this PC, never a cloud model.

**Comparing transcription recipes on your own audio.** The Benchmark Lab needs a golden set; `python -m tools.asr_bench TITLE_ID --config RECIPE --config RECIPE ...` instead runs one stretch of a title's stored audio (`--from`/`--to` in seconds, default the first 300) through several recipes and writes `asr-bench-report.md` to the data folder. A recipe is a backend, a model and a few options, for example `whisper:large-v3-turbo`, `whisper:kotoba-v2,align=on`, `whisper:large-v3-turbo,vad=sensitive,beam=1`, `whisper:large-v3,difficult=on`, `qwen3_asr_vad,detector=asmr` or `qwen3_asr_long`; the first is the baseline, and the full grammar is in `--help` and `docs/asr-experiments.md`. It scores against `--reference FILE.srt` (hand-corrected subtitles on the title's timeline) or, without one, against the title's current lines. Without `--yes` it is a dry run that lists the recipes, the models they would load and a rough time, and writes nothing; with `--yes` it waits for any running GPU job, unloads models between recipes and saves nothing to the title. The report gives per recipe time, real-time factor, peak GPU memory, merged and missed lines, start/end timing error, 1 - CER (1 - WER for space-delimited languages), repetition loops, stock-phrase hallucinations, lines over silence and a side-by-side listing of the lines that differ.

## Notes & tips

- The first run downloads the Whisper model (a few hundred MB to ~3GB, once).
- Settings > Display has Page width, Text size and Spacing (Comfortable or Compact) for this browser. Compact tightens gaps and padding on a computer with a mouse; phones and touch screens keep the larger touch targets. Style switches the look: Frost (the default) or Soft (rounder, raised cards, violet accent); it works with every theme. In Soft, a primary button that can't be pressed yet (such as Search with no title) shows greyed with readable text, as in Frost, instead of a blank violet pill.
- No GPU is required, but a GPU makes transcription much faster (Settings > System > Jobs and GPU).
- Alignment is an approximation that interpolates timing for lines Whisper didn't clearly catch; skim the review table before exporting.
- Your API keys and files never leave your machine except for the direct call to your chosen translation/TTS provider.
